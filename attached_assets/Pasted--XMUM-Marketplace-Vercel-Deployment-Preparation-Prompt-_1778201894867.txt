## CONTEXT: WHO YOU ARE AND WHAT THIS PROJECT IS

You are continuing work on the XMUM Marketplace project. This is a React + Vite + TypeScript SPA that lives inside a pnpm monorepo at `artifacts/xmum-market/`. The backend is entirely Firebase (Auth, Firestore, Storage) — there is no Express server to deploy.

## WHY THIS PREP IS NEEDED (READ BEFORE DOING ANYTHING)

The project currently has these characteristics that will cause Vercel builds to fail if not addressed:

**Problem 1 — Deep monorepo structure**
The app lives at `artifacts/xmum-market/` inside a workspace root. Vercel needs to know where to find the app and how to build it. Without configuration, it will try to build from the root and fail.

**Problem 2 — Replit-specific Vite plugins**
`vite.config.ts` includes `@replit/vite-plugin-cartographer`, `@replit/vite-plugin-dev-banner`, and `@replit/vite-plugin-runtime-error-modal`. These already have conditional guards checking `process.env.REPL_ID`, so the first two won't run on Vercel. The runtime error modal runs unconditionally in production — it must be fully guarded or removed from the build.

**Problem 3 — `tsconfig.json` extends `../../tsconfig.base.json`**
The app's `tsconfig.json` extends `../../tsconfig.base.json` (the workspace root). This path won't resolve on Vercel since only the `artifacts/xmum-market/` subtree will be deployed. The `tsconfig.json` needs to be self-contained.

**Problem 4 — `@workspace/api-client-react` dependency**
`package.json` lists `"@workspace/api-client-react": "workspace:*"` as a devDependency. This is a pnpm workspace package that won't be resolvable on Vercel. It needs to be removed (it is only used by shadcn tooling, not by the app's actual source code).

**Problem 5 — `@assets` path alias points outside the app directory**
`vite.config.ts` has `"@assets": path.resolve(import.meta.dirname, "..", "..", "attached_assets")`. This points to `attached_assets/` at the workspace root, two levels up. On Vercel this path won't exist. The alias needs to be updated to point to `public/` or removed if not used in source.

**Problem 6 — SPA routing (404 on page refresh)**
Vercel serves SPAs as static files. Any direct URL like `/listing/abc` or `/settings` will return a 404 unless a `vercel.json` rewrites all paths to `index.html`. This is required for `wouter`-based routing to work on page reload.

**Problem 7 — Build output directory**
The current `vite.config.ts` sets `outDir: "dist/public"`. Vercel needs to be pointed at this exact output directory.

**Problem 8 — `minimumReleaseAge` in `pnpm-workspace.yaml`**
The workspace root `pnpm-workspace.yaml` has `minimumReleaseAge: 1440` — this requires packages to be 24h old before installing. This setting applies workspace-wide. For Vercel's isolated build environment, this should not be an issue since all packages are already published, but the `pnpm-workspace.yaml` at the app level should handle this gracefully.

**Problem 9 — esbuild platform overrides**
`pnpm-workspace.yaml` excludes non-linux platforms from esbuild (e.g. `"esbuild>@esbuild/darwin-arm64": "-"`). Vercel builds on Linux so this is fine — but a standalone `pnpm-workspace.yaml` in the app directory must not accidentally exclude the Linux build either.

### TASK 5 — Create `vercel.json` at the app root

**File:** `artifacts/xmum-market/vercel.json` *(new file)*

Create this file. It tells Vercel where to build from, what command to use, where the output is, and how to handle SPA routing:

```json
{
  "buildCommand": "pnpm run build",
  "outputDirectory": "dist",
  "installCommand": "pnpm install --frozen-lockfile",
  "framework": null,
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ],
  "headers": [
    {
      "source": "/assets/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    },
    {
      "source": "/(.*).js",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    },
    {
      "source": "/(.*).css",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    },
    {
      "source": "/",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=0, must-revalidate" }
      ]
    },
    {
      "source": "/index.html",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=0, must-revalidate" }
      ]
    }
  ]
}
```

> The `rewrites` block is what makes `wouter` SPA routing work on page reload — without it, a direct visit to `/listing/abc123` returns a 404. The `headers` blocks set correct caching: immutable cache for fingerprinted assets, no-cache for `index.html`.

## AFTER REPLIT FINISHES — STEPS TO DEPLOY ON VERCEL

Once Replit confirms the build succeeds, do the following on Vercel:

### Step 1 — Connect your GitHub repo
1. Push all changes to GitHub from Replit
2. Go to vercel.com → New Project → Import from GitHub
3. Select the `XMUM-Marketplace` repository

### Step 2 — Configure the project in Vercel's UI
When Vercel asks for build settings, fill in:
- **Framework Preset:** Other (not Vite — we have our own `vercel.json`)
- **Root Directory:** `artifacts/xmum-market`
- **Build Command:** `pnpm run build` (or leave blank — `vercel.json` specifies it)
- **Output Directory:** `dist` (or leave blank — `vercel.json` specifies it)
- **Install Command:** `pnpm install --frozen-lockfile`

### Step 3 — Add environment variables
In Vercel project settings → Environment Variables, add all 7 variables from `.env.example` with the real values from your Firebase console. Make sure to set them for **Production**, **Preview**, and **Development** environments.

### Step 4 — Deploy
Click Deploy. The first build may take 2-3 minutes.

### Step 5 — Add Vercel domain to Firebase Auth
Once deployed, copy your `.vercel.app` URL and add it to Firebase Console → Authentication → Settings → Authorised domains.
