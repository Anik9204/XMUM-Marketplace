PART 2 — Fix A: markAsSold swallows timeout as success

FILE TO EDIT: artifacts/xmum-market/src/lib/listings.ts

THE BUG:
markAsSold uses Promise.race with a timeout that resolves (not rejects) on expiry:
  new Promise<void>((resolve) => setTimeout(resolve, 6_000))
This means if the Firestore write is slow, the race resolves with undefined — the caller
thinks the update succeeded but the listing may still be active in Firestore.

THE FIX:
Change the timeout inside markAsSold from resolve to reject, exactly like updateListing
and bumpListing already do. Find this exact block inside markAsSold:

  await Promise.race([
    updateDoc(doc(db, "listings", id), { status: "sold" }),
    new Promise<void>((resolve) => setTimeout(resolve, 6_000)),
  ]);

Change it to:

  await Promise.race([
    updateDoc(doc(db, "listings", id), { status: "sold" }),
    new Promise<never>((_, reject) =>
      setTimeout(() => reject(new Error("timeout:mark-as-sold")), 6_000)
    ),
  ]);

Do not touch any other function in listings.ts.

PART 2 — Fix B: Photo upload silently skips failed photos

FILE TO EDIT: artifacts/xmum-market/src/pages/PostPage.tsx

THE BUG:
In handleSubmit, each photo upload failure is caught and silently skipped with only a
console.warn. The listing gets created with fewer photos than the user selected, with no
error shown. For rental listings this is especially bad since they require at least 2 photos
but the pre-submit check passes before uploads happen.

THE FIX:
Find this block inside handleSubmit in PostPage.tsx:

      const urls: string[] = [];
      for (const f of photos) {
        try {
          const url = await withTimeout(uploadPhoto(f, user.uid), 30_000, "photo-upload");
          urls.push(url);
        } catch (photoErr: any) {
          console.warn("[PostPage] Photo skipped:", photoErr?.message);
        }
      }

Replace it with:

      const urls: string[] = [];
      for (const f of photos) {
        const url = await withTimeout(uploadPhoto(f, user.uid), 30_000, "photo-upload");
        urls.push(url);
      }

The error is already caught by the outer try/catch in handleSubmit which sets the error
message and calls setLoading(false). The existing catch block for "timeout:photo-upload"
in the outer catch already handles this correctly:
  else if (msg.startsWith("timeout:photo-upload")) setError("A photo upload timed out...")

So removing the inner try/catch means any photo failure now surfaces to the user as a
proper error instead of silently continuing. Do not change anything else in this function.
