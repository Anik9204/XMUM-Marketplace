## Task: Fix listing delete — permission denied when reading reports collection

### Root cause
`listingHasActiveReport()` in `artifacts/xmum-market/src/lib/reportHold.ts` queries the `reports` collection directly. Regular students cannot read `reports` (Firestore rules restrict it to editors/admins only). This causes a `permission-denied` error when any student tries to delete their own listing.

### Fix: replace the reports query with a direct listing field check

In `artifacts/xmum-market/src/lib/reportHold.ts`, change the `listingHasActiveReport` function.

BEFORE:
```ts
export async function listingHasActiveReport(listingId: string): Promise<boolean> {
  const q = query(
    collection(db, "reports"),
    where("listingId", "==", listingId),
    where("status", "in", ["pending", "reviewed"]),
    limit(1)
  );
  const snap = await getDocs(q);
  return !snap.empty;
}
```

AFTER:
```ts
export async function listingHasActiveReport(listingId: string): Promise<boolean> {
  try {
    const snap = await getDoc(doc(db, "listings", listingId));
    if (!snap.exists()) return false;
    return snap.data().isReportHeld === true;
  } catch {
    return false;
  }
}
```

Also add `getDoc` to the imports at the top of the file. The current import line is:
```ts
import {
  collection, query, where, getDocs, updateDoc, doc, limit,
} from "firebase/firestore";
```

Change it to:
```ts
import {
  collection, query, where, getDocs, getDoc, updateDoc, doc, limit,
} from "firebase/firestore";
```

### Why this works
The `listings` collection is publicly readable (`allow read: if true`). The `isReportHeld` field is already set to `true` on a listing when an admin places a hold. So checking the listing document directly is both safe and accurate — no need to query the restricted `reports` collection.

Do NOT change `shopListingHasActiveReport` — it is only called from admin-side code where editors can read reports.
