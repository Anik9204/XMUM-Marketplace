=================================================================
BUG — ACCOUNT DELETION DOES NOT CLEAN UP STORAGE FILES
=================================================================

SYMPTOM:
When a user deletes their account, only their Firebase Auth 
credentials (and possibly their Firestore users/{uid} doc) are 
removed. The following Storage files are left behind as orphans:

  1. avatars/{uid}/avatar.*          — their profile photo
  2. listings/{uid}/{listingId}/*    — ALL images for every listing 
     they ever posted (up to 3 photos per listing)

This is both a storage cost leak and a privacy violation — deleted 
users' photos remain publicly accessible via their download URLs.

FILES TO READ FIRST (read all of these before writing anything):
  - src/lib/auth.ts          (contains the deleteAccount function)
  - src/lib/userProfile.ts   (contains uploadAvatar, getProfile)
  - src/lib/listings.ts      (contains getUserListings, deleteListing,
                               and any existing deleteObject calls)
  - src/lib/types.ts         (Listing and UserProfile interfaces — 
                               need to know imageUrls/photoURLs field 
                               names on a Listing document)
  - src/pages/SettingsPage.tsx (where deleteAccount is called from 
                               the UI — need to see loading/error 
                               state handling)

=================================================================
REQUIRED FIX — CASCADING DELETION SEQUENCE
=================================================================

The deletion must follow this strict ORDER to avoid permission 
errors. Firebase Storage delete rules require auth.uid == userId, 
so ALL storage deletes MUST happen while the user is still 
authenticated — before deleteUser() is called.

Step 1 — Fetch all user's listings from Firestore FIRST
  Call getUserListings(uid) to get every listing document 
  belonging to this user. We need the imageUrls (or photos, 
  or whatever the field is named in types.ts — check it) 
  from each listing to build the Storage delete list.

Step 2 — Delete all listing Storage files IN PARALLEL
  For each listing, for each image URL in its imageUrls array:
  - Parse the Storage path from the download URL, OR
  - Reconstruct the path as: listings/{uid}/{listingId}/{filename}
  
  IMPORTANT: Use Firebase Storage's ref(storage, path) + 
  deleteObject(ref) — NOT fetch() on the URL directly.
  
  If a listing's imageUrls field stores full download URLs 
  (https://firebasestorage.googleapis.com/...), extract the 
  path using decodeURIComponent on the URL's path segment 
  between "/o/" and "?alt=". Example helper:
  
    function storagePathFromUrl(url: string): string {
      const match = url.match(/\/o\/(.+?)\?/);
      if (!match) throw new Error('Invalid storage URL');
      return decodeURIComponent(match[1]);
    }
  
  Wrap each deleteObject in try/catch — if a file is already 
  gone (storage/object-not-found), swallow the error silently 
  and continue. Never let a missing file abort the whole 
  deletion sequence.
  
  Run all listing image deletes with Promise.allSettled() 
  (NOT Promise.all — allSettled never throws even if one fails).

Step 3 — Delete all listing Firestore DOCUMENTS in parallel
  For each listing from Step 1, call deleteDoc on 
  listings/{listingId}. 
  Use the same 6-second race-timeout pattern already used 
  elsewhere in the codebase (offline persistence can block):
  
    const withTimeout = (p: Promise<any>, ms: number) =>
      Promise.race([p, new Promise(res => setTimeout(res, ms))]);
  
  Run all deleteDoc calls with Promise.allSettled().

Step 4 — Delete the avatar from Storage
  Delete the file at: avatars/{uid}/avatar.{ext}
  
  The extension may vary (jpg, png, webp). The safest approach 
  is to read userProfile.avatarUrl from Firestore BEFORE deleting 
  the users/{uid} doc, then use storagePathFromUrl() to get the 
  exact path. If avatarUrl is null/empty, skip this step silently.
  
  Wrap in try/catch — swallow storage/object-not-found.

Step 5 — Delete the Firestore users/{uid} document
  deleteDoc(doc(db, 'users', uid))
  Wrap in the 6s race-timeout. Swallow errors.

Step 6 — Delete the Firebase Auth account
  THIS MUST BE LAST.
  Call user.delete() (or deleteUser(user) from firebase/auth).
  
  IMPORTANT: Firebase Auth requires recent sign-in for account 
  deletion. If this throws an auth/requires-recent-login error, 
  catch it specifically and:
    a) Do NOT proceed with deletion
    b) Return a specific error code the UI can detect
    c) The UI should then prompt the user to re-enter their 
       password, call reauthenticateWithCredential(), then 
       retry the entire deleteAccount() flow from Step 1.
