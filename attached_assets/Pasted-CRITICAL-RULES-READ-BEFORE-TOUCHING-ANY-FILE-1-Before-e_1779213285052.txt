## PART 2 — RENTAL ARCHIVE SYSTEM (MARKET APP)
 
**Architecture decision:** The correct approach is NOT to change the existing `rentalAuditLogs` collection (which already logs T&C acceptance). Instead, create a NEW `rentalArchivedListings` Firestore collection that stores a complete snapshot of a rental listing at the moment it is deleted. This is separate from T&C logs and serves a different purpose: it is the evidentiary archive of the actual listing content.
 
**Why this is the best architecture:**
- `rentalAuditLogs` = proof of consent (who accepted T&C, when, for which listing) — UNCHANGED
- `rentalArchivedListings` = complete listing snapshot for moderation/legal evidence — NEW
- Separation of concerns; each collection has a single clear purpose
- Admins can still cross-reference by `listingId`

```tsx
              <div className="overflow-x-auto">
                <table className="w-full text-sm">
                  <thead>
                    <tr className="bg-gray-50 dark:bg-slate-700/50 border-b border-gray-200 dark:border-slate-600">
                      <th className="text-left px-4 py-3 text-xs font-semibold text-slate-500 dark:text-slate-400 uppercase tracking-wide whitespace-nowrap">Accepted At</th>
                      <th className="text-left px-4 py-3 text-xs font-semibold text-slate-500 dark:text-slate-400 uppercase tracking-wide whitespace-nowrap">User Email</th>
                      <th className="text-left px-4 py-3 text-xs font-semibold text-slate-500 dark:text-slate-400 uppercase tracking-wide whitespace-nowrap">User ID</th>

                    {filteredLogs.map((log) => (
                      <tr key={log.id} className="hover:bg-gray-50 dark:hover:bg-slate-700/30 transition-colors">

                        <td className="px-4 py-3 text-xs text-slate-700 dark:text-slate-200 font-medium whitespace-nowrap">{log.userEmail}</td>

                          <span className="font-mono text-[10px] text-slate-400 dark:text-slate-500 bg-gray-100 dark:bg-slate-700 px-2 py-0.5 rounded">{log.userId}</span>
                        </td>
                        <td className="px-4 py-3 text-xs text-slate-700 dark:text-slate-200 max-w-[200px] truncate">{log.listingTitle}</td>
                        <td className="px-4 py-3">
                          <span className="font-mono text-[10px] text-slate-400 dark:text-slate-500 bg-gray-100 dark:bg-slate-700 px-2 py-0.5 rounded">{log.listingId}</span>
                        </td>
                        <td className="px-4 py-3">
                          <span className="text-[10px] bg-amber-100 dark:bg-amber-950 text-amber-700 dark:text-amber-400 px-2 py-0.5 rounded-full font-medium">{log.tcVersion}</span>
                        </td>
                        <td className="px-4 py-3 text-[10px] text-slate-400 dark:text-slate-500 max-w-[240px] truncate" title={log.userAgent}>{log.userAgent}</td>
                      </tr>
                    ))}
                  </tbody>
                </table>
              </div>
            </div>
          )}
        </>
      )}
    </div>
  );
}
```

### 2C — Add Firestore Rules for `rentalArchivedListings`
 
In `artifacts/xmum-market/firestore.rules`, add the following rule inside the `match /databases/{database}/documents` block. Add it near the `rentalAuditLogs` rule if one exists, or after it:
 
```
match /rentalArchivedListings/{docId} {
  // Users can create (write) an archive record when deleting their own rental
  allow create: if request.auth != null
    && request.resource.data.archivedByUid == request.auth.uid;
  // Only admins/editors can read archived records (enforced client-side via role check)
  // Firestore rule: allow read only to authenticated users (admin role checked in app)
  allow read: if request.auth != null;
  // Only admins can delete archived records (enforced via admin app only)
  allow delete: if false; // all deletes go through admin app with server-side check
  allow update: if false;
}
```
