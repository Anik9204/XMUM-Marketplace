═══════════════════════════════════════════
ISSUE: emailVerified is always false in Firestore users documents
═══════════════════════════════════════════

BACKGROUND:
Every user in the Firestore "users" collection has a field 
"emailVerified: false" even though many users have already verified 
their email through Firebase Auth. 

The root cause is that the app saves emailVerified at signup time 
from user.emailVerified (which is always false at the moment of 
account creation, before the user clicks the verification link). 
After the user clicks the verification link, Firebase Auth updates 
the token — but nothing ever writes that updated value back to 
the Firestore users document. So it stays false forever.

This needs to be fixed in the XMUM Market app 
(artifacts/xmum-market), NOT the admin app.

═══════════════════════════════════════════
THE FIX — TWO SURGICAL CHANGES ONLY
═══════════════════════════════════════════

CHANGE 1 — Update emailVerified in Firestore on every login

FILE: Find the file in artifacts/xmum-market/src that handles 
Firebase Auth state changes — this is likely AuthContext.tsx or 
a similar auth context/provider file. Look for the 
onAuthStateChanged listener.

Inside the onAuthStateChanged callback, after the user object 
is confirmed to be non-null and their Firestore profile has been 
loaded, add ONE extra step:

  If user.emailVerified is true AND the stored Firestore 
  emailVerified field is false, update the Firestore users 
  document for that user to set emailVerified: true.

Use updateDoc with { emailVerified: true } — do NOT overwrite 
the entire document.

Wrap this in a try/catch — it is non-critical and must never 
crash the auth flow or block the user from logging in.

Only run this update when needed (emailVerified is true in Auth 
but false in Firestore) to avoid unnecessary Firestore writes 
on every page load.

IMPORTANT: Do NOT change anything else in the auth flow. Do NOT 
change how the user profile is loaded, how state is set, how 
loading works, or any other part of the onAuthStateChanged logic. 
Only add this one conditional updateDoc call.

CHANGE 2 — Reload the Firebase Auth user token after email 
verification

FILE: Find the file in artifacts/xmum-market/src that handles 
email verification — this could be an EmailVerification page, 
a callback/redirect handler, or wherever the app detects that 
the user has just verified their email.

If such a page or handler exists, add a call to 
user.reload() after verification is confirmed. This forces 
Firebase Auth to refresh the token so user.emailVerified 
becomes true immediately without requiring the user to 
sign out and back in.

After calling user.reload(), also update the Firestore document:
  updateDoc(doc(db, "users", user.uid), { emailVerified: true })

Wrap in try/catch — non-critical.

If no email verification handler page exists, skip Change 2 
and only apply Change 1.
