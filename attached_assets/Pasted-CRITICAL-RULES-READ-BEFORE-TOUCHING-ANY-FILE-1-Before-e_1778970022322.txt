### BUG 2 — Admin `deleteShop` does not clean up Storage files

**What is broken:**
`artifacts/xmum-admin/src/lib/firebase.ts` has a `deleteShop` function that
cascade-deletes Firestore documents (shopListings, shopInquiries, shopOrders,
shopReviews, then the shop doc itself). However, it does **not** delete the
shop's Firebase Storage files — banner images (`shopBanners/`), logo images
(`shopLogos/`), and shop listing photos (`shopListingPhotos/`). These become
orphaned files that accumulate in Storage indefinitely.

By contrast, the XMUM Market app's own `deleteShopCompletely` in
`artifacts/xmum-market/src/lib/shops.ts` already does this correctly —
it extracts storage paths from URLs and deletes them.

**Where to fix — XMUM Admin (`artifacts/xmum-admin/`):**

**File: `src/lib/firebase.ts`**

Rewrite the `deleteShop` function to also delete Storage files. Model it on the
market app's `deleteShopCompletely` implementation. Here is the complete
replacement:

```ts
export async function deleteShop(shopId: string) {
  const { writeBatch } = await import("firebase/firestore");
  const { ref: storageRef, deleteObject } = await import("firebase/storage");

  const shopSnap = await getDoc(doc(db, "shops", shopId));
  if (!shopSnap.exists()) throw new Error("Shop not found");

  const relatedCollections = ["shopListings", "shopInquiries", "shopOrders", "shopReviews"];

  // Fetch all related docs in parallel
  const snaps = await Promise.all(
    relatedCollections.map((col) =>
      getDocs(query(collection(db, col), where("shopId", "==", shopId))).catch(() => null)
    )
  );

  // Delete Storage files — listing photos
  const storageJobs: Promise<void>[] = [];
  const listingsSnap = snaps[0];
  if (listingsSnap) {
    for (const d of listingsSnap.docs) {
      for (const url of (d.data().photos ?? []) as string[]) {
        const path = storagePathFromUrl(url);
        if (path) storageJobs.push(deleteObject(storageRef(storage, path)).catch(() => {}));
      }
    }
  }

  // Delete Storage files — shop banner and logo
  const sd = shopSnap.data();
  for (const url of [sd.bannerUrl, sd.logoUrl].filter(Boolean) as string[]) {
    const path = storagePathFromUrl(url);
    if (path) storageJobs.push(deleteObject(storageRef(storage, path)).catch(() => {}));
  }
  await Promise.allSettled(storageJobs);

  // Batch-delete all Firestore documents (max 400 per batch)
  const allDocs = snaps.flatMap((s) => s?.docs ?? []);
  const BATCH_SIZE = 400;
  for (let i = 0; i < allDocs.length; i += BATCH_SIZE) {
    const batch = writeBatch(db);
    for (const d of allDocs.slice(i, i + BATCH_SIZE)) batch.delete(d.ref);
    await batch.commit();
  }

  // Delete the shop document last
  await deleteDoc(doc(db, "shops", shopId));
}
```

Then add the `storagePathFromUrl` helper to `src/lib/firebase.ts` (if not
already present):

```ts
function storagePathFromUrl(url: string): string | null {
  try {
    const decodedUrl = decodeURIComponent(url);
    const match = decodedUrl.match(/\/o\/(.+?)(\?|$)/);
    return match ? match[1] : null;
  } catch {
    return null;
  }
}
```

Make sure the `storage` instance is imported/available in this file (it already
is — `export const storage = getStorage(app)` exists).

### BUG 3 — Admin `getShops` maps `category` as a single string into `shopCategories` array, but market stores it as a single `category` string field

**What is broken:**
In `artifacts/xmum-admin/src/lib/firebase.ts`, `getShops` maps:
```ts
shopCategories: data.category ? [data.category] : (data.shopCategories ?? []),
```

This means the admin Shops table category filter works correctly. However the
admin `AdminShop` type in `src/lib/types.ts` declares:
```ts
shopCategories?: string[];
```

But the market-side `Shop` type (`artifacts/xmum-market/src/lib/types.ts`)
uses:
```ts
category: ShopCategory;  // single string, not an array
```

This is not a breaking bug today, but it causes incorrect category data in any
admin export/CSV and will cause confusion as the codebase grows. The
`shopCategories` array in the admin type should remain (the admin panel supports
multi-category display), but the mapping in `getShops` is already correct.
No code change needed for this item — just verify the existing mapping
(`data.category ? [data.category] : (data.shopCategories ?? [])`) is present
and intact in `getShops`.

### BUG 5 — `getRecentShopListings` shows listings from suspended shops

**What is broken:**
`getRecentShopListings` in `artifacts/xmum-market/src/lib/shops.ts` fetches the
most recent shop listings globally and filters only by `isActive`. It does not
check whether the parent shop is suspended. This is the function used on the
homepage/Campus Market page to display recently listed items — so suspended shop
listings can still appear there.

This is covered by the fix in BUG 1 above. Specifically, this function currently
skips the `shopStatuses` parent-shop-check that `getAllShopListings` uses.
As part of BUG 1's fix, add that same check to `getRecentShopListings`:

After fetching and filtering listings by `isActive`, add:
```ts
const shopIds = [...new Set(listings.map((l) => l.shopId))];
const shopStatuses: Record<string, boolean> = {};
await Promise.all(
  shopIds.map(async (id) => {
    try {
      const s = await getDoc(doc(db, "shops", id));
      shopStatuses[id] = s.exists() && s.data()?.isActive !== false && s.data()?.isSuspended !== true;
    } catch {
      shopStatuses[id] = false;
    }
  })
);
return listings
  .filter((l) => shopStatuses[l.shopId] !== false)
  .slice(0, limitCount);
```
