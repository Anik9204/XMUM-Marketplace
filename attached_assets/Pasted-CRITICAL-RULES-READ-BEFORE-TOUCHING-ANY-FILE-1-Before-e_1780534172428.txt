FILE TO EDIT: artifacts/xmum-market/src/lib/messaging.ts

ROOT CAUSE:
clearConversation() stamps clearedAt.{uid} on the conversation document but
does NOT reset unreadCount.{uid} to 0. The subscribeToUnreadCount() listener
in Layout.tsx sums unreadCount[uid] across ALL conversations in Firestore —
including ones the user has cleared without reading. The conversation is
hidden from the UI list (the visibleConversations filter uses clearedAt), but
the badge in the nav bar keeps counting the stale unreadCount value.

THE FIX — one surgical change to the clearConversation function only.

Find this exact function in messaging.ts:

export async function clearConversation(convId: string, uid: string): Promise<void> {
  await updateDoc(doc(db, "conversations", convId), {
    [`clearedAt.${uid}`]: Date.now(),
  });
}

Replace it with:

export async function clearConversation(convId: string, uid: string): Promise<void> {
  await updateDoc(doc(db, "conversations", convId), {
    [`clearedAt.${uid}`]: Date.now(),
    [`unreadCount.${uid}`]: 0,
  });
}

WHAT CHANGES: clearConversation now resets unreadCount.{uid} to 0 in the
same atomic updateDoc call as the clearedAt stamp.

WHY THIS FIX IS COMPLETE AND SAFE:
- It is one atomic write — both fields update together, no partial state.
- subscribeToUnreadCount() is a live onSnapshot listener. The moment this
  write lands in Firestore, every open browser tab recalculates the total
  and the nav badge updates to the correct number immediately. No page
  refresh needed. All existing users are fixed instantly on deployment.
- clearConversation is called from two places in MessagesPage.tsx:
  handleClear (clears from within the open chat) and handleClearFromList
  (clears from the conversation list row). Both benefit from this fix
  automatically — no changes needed in MessagesPage.tsx.
- markConversationRead() is unchanged — it still handles the read case
  when a user opens and reads a conversation normally.
- The clearedAt logic that hides the conversation from the list UI is
  completely unchanged.
- No Firestore rules changes are needed. The existing conversations update
  rule already permits participants to update unreadCount.
