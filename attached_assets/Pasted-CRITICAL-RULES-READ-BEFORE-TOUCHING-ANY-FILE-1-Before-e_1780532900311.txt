ROOT CAUSE (confirmed):
The backfill in userProfile.ts uses the Firestore SDK updateDoc() to write
to listings documents. The market app's Firestore is initialized with
experimentalForceLongPolling: true — a persistent connection that suffers
from stale auth tokens. All listing writes in listings.ts deliberately use a
REST layer (restUpdateDoc) instead of the SDK for exactly this reason.
The backfill uses SDK updateDoc directly, gets a stale token, Firestore
silently rejects it with permission-denied, and the .catch(() => {}) swallows
the error. The user sees "Saved!" but the listings are never updated.

THE FIX — two surgical changes across two files:

════════════════════════════════════════════════════════════
FILE 1: artifacts/xmum-market/src/lib/listings.ts
════════════════════════════════════════════════════════════

The restUpdateDoc function is currently private (not exported). We need to
expose a thin public function that uses it to backfill userName on all
listings for a given user. Add this new exported function at the END of
the file, after all existing exports:

/**
 * Backfills the userName field on all listings owned by a given user.
 * Uses the REST layer (not the Firestore SDK) to avoid the stale-token
 * issue that affects SDK writes through the persistent long-poll connection.
 * Called by updateProfile() in userProfile.ts when fullName changes.
 * Skips report-held listings (Firestore rules block their updates).
 */
export async function backfillListingUserName(
  userId: string,
  newUserName: string
): Promise<void> {
  const snap = await getDocs(
    query(collection(db, "listings"), where("userId", "==", userId))
  );
  await Promise.all(
    snap.docs
      .filter((d) => d.data().isReportHeld !== true)
      .map((d) =>
        restUpdateDoc("listings", d.id, { userName: newUserName }).catch(() => {})
      )
  );
}

IMPORTANT: getDocs, query, collection, where are already imported at the
top of listings.ts. Do NOT add duplicate imports.
restUpdateDoc is already defined earlier in listings.ts. Do NOT move or
modify it — just call it from this new function.
