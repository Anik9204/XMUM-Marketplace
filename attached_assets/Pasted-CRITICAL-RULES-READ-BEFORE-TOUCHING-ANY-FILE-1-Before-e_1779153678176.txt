TASK: When the user presses the Post button (desktop nav link or mobile FAB),
they should land on the PostPage pre-selected to the same tab they were
browsing on the HomePage. e.g. if they were on "lost-found" tab, pressing
Post opens the form already on "Lost & Found".

IMPORTANT NOTES before you start:
- PostPage already supports a ?type= URL query param. Line ~316 in PostPage.tsx:
    const params = new URLSearchParams(window.location.search);
    const urlType = params.get("type") as ListingType | null;
  This already sets the form tab from the URL. Do NOT touch PostPage.tsx at all.
- The rental tab is special: PostPage shows the RentalTcModal consent first
  if the user switches to rental and hasn't accepted yet. This MUST still happen.
  Passing ?type=rental in the URL will pre-select rental, but since the existing
  URL param useEffect (line ~316) calls setType directly (not handleTypeChange),
  it bypasses the TC modal. We need to fix this carefully.

--- STEP 1: Fix PostPage.tsx for rental TC consent when arriving via URL ---

File: artifacts/xmum-market/src/pages/PostPage.tsx

Find the useEffect that reads the ?type= URL param (around line 316):

    const validTypes: ListingType[] = ["buy-sell", "lost-found", "jobs", "assistance", "rental"];

      setType(urlType);
      setCategory(defaultCategoryForType(urlType));
    }
  }, []);

Replace it with this version that shows TC modal if rental is requested but not yet accepted:
  useEffect(() => {
    const params = new URLSearchParams(window.location.search);
    const urlType = params.get("type") as ListingType | null;
    const validTypes: ListingType[] = ["buy-sell", "lost-found", "jobs", "assistance", "rental"];
    if (urlType && validTypes.includes(urlType)) {
      if (urlType === "rental" && !tcAccepted) {
        setShowTcModal(true);
      } else {
        setType(urlType);
        setCategory(defaultCategoryForType(urlType));
      }
    }
  }, []);

--- STEP 2: Add shared activeTab state to HomePage so the FAB and nav link can read it ---

The Layout component does NOT receive any props about the active tab — it only
knows the URL location. We need a lightweight way to share the active tab from
HomePage to the Layout's post buttons WITHOUT passing props through Layout
(since Layout wraps all pages and we don't want to add complexity).

The cleanest approach: store the active homepage tab in sessionStorage when
it changes, and read it in Layout when building the /post href.

File: artifacts/xmum-market/src/pages/HomePage.tsx

Find the handleTabChange function:
  const handleTabChange = (tab: ListingType) => {
    setActiveTab(tab);
    ...
  };

Add one line inside it, right after setActiveTab(tab):
  sessionStorage.setItem("xmum_home_active_tab", tab);

Also, when the component mounts, set the initial value. Find the state declaration:
  const [activeTab, setActiveTab] = useState<ListingType>("buy-sell");

After that line, add a useEffect (place it near the top with the other useEffects):
  useEffect(() => {
    sessionStorage.setItem("xmum_home_active_tab", activeTab);
  }, [activeTab]);

Also, add a useEffect that clears the stored tab when the user navigates AWAY
from HomePage — so that if they go to a different page and then press Post,
it goes to /post with no ?type= param (default form). Find the return in the
component or add near the other cleanup useEffects:
  useEffect(() => {
    return () => {
      sessionStorage.removeItem("xmum_home_active_tab");
    };
  }, []);

Do NOT change any JSX, any other state, or any other logic in HomePage.tsx.

We need a helper that reads the stored tab and builds the correct href.
This helper must be defined INSIDE the Layout component function body
