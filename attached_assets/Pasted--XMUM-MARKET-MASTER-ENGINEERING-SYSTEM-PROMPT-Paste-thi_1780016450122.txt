## ARCHITECTURAL PATTERNS — FOLLOW EXACTLY

### Firebase HMR guard (never change)
```typescript
const app = getApps().length ? getApp() : initializeApp(firebaseConfig);
```

### Firestore config (never change)
```typescript
experimentalForceLongPolling: true  // Required for Replit proxy environment
```

### AI Moderation flow (PostPage, EditListingPage, ShopManagementPanel)
1. Photos upload to Firebase Storage → get download URLs
2. URLs + text passed to `moderateContent` Cloud Function
3. If BLOCKED → delete uploaded photos + abort + show error
4. If FLAGGED → proceed + write to `aiFlags` collection via `writeAiFlag()`
5. If SAFE → proceed normally
6. **On any function error → fail open (SAFE)** — never hard-block students

### Rich text storage format
Descriptions are stored as plain text with these markers:
- `**text**` → bold
- `*text*` → italic
- `++text++` → large text
Always use `stripRichText(text)` for card previews and truncated displays.
Always use `<RichTextDisplay text={...} className="..." />` for full description renders.
These markers are intentionally human-readable for AI moderation.

### Draft system (PostPage)
Auto-saves to localStorage every 30 seconds and on blur. Key: `DRAFT_KEY` constant.
Do not remove or interfere with `saveDraft()`, `restoreDraft()` functions.

### Description editing pattern
All multi-line description fields use a fullscreen modal editor — never an inline textarea.
Modal opens on button click → user edits in fullscreen → Done saves, Cancel discards.
The `RichTextEditor` component is used inside all description modals.

### Denormalized counter pattern
Counters (`totalListings`, `activeListingCount`, etc.) use Firestore `increment()`.
They CAN drift. When displaying to users, always guard: `Math.max(0, value ?? 0)`.
When deleting through ANY path (client or admin), always fire the corresponding `increment(-1)`.

### Listing type system
`ListingType = "buy-sell" | "lost-found" | "jobs" | "assistance" | "rental"`
`HomeTab = "all" | ListingType` — "all" is local UI state ONLY, never added to ListingType in types.ts.

### Pricing
Prices stored in **cents (integer)** for marketplace listings (e.g. RM 10.00 = 1000).
Shop listing prices stored in **ringgit (float)**.
`CentsInput` component in PostPage handles the conversion display.

### Pagination
`PAGE_SIZE = 30` in `listings.ts`. Cursor-based pagination using `sortKey DESC`.

### Mobile nav
5-item bottom nav: Home / Search / Shops / Messages / Profile.
Desktop: nav links in header. Never add new items to mobile bottom nav without explicit instruction.

### User roles
`users/{uid}.role`: `undefined/user` → regular student | `editor` → can manage listings/reports | `admin` → full access

## KNOWN TRAPS — NEVER REPEAT THESE

1. **`shop.totalListings` can be negative** — always `Math.max(0, shop.totalListings ?? 0)` in UI. The counter drifts when listings are deleted through admin or Firebase Console without calling `increment(-1)`.

2. **Admin deletion path must decrement counters** — `xmum-admin/src/lib/firebase.ts` listing deletion must always call `increment(-1)` on `shops/{shopId}.totalListings`. Same applies to any deletion path in functions.

3. **`aiFlags` collection, NOT `aiFlaggedContent`** — the handoff doc is wrong. Code is the source of truth.

4. **`authDomain` must stay as `xmum--market.firebaseapp.com`** — never change to `www.xmummarket.com` or any custom domain. Firebase Auth breaks silently.

5. **CSP must be updated in BOTH `vercel.json` AND `index.html`** — updating only one leaves a broken dev or production experience.

6. **Cloud Functions are NOT deployed by GitHub push** — Vercel only deploys the two frontend apps. Functions require manual `firebase deploy`.

7. **`experimentalForceLongPolling: true`** must stay in firebase.ts — Replit's proxy breaks standard WebSocket Firestore connections without it.

8. **Offline persistence is intentionally disabled** — do not enable `enableIndexedDbPersistence` or `enableMultiTabIndexedDbPersistence`. Writes intentionally fail fast.

9. **Never use react-router-dom** — this project uses wouter exclusively.

10. **Never add framer-motion or GSAP** — use Tailwind animations and plain CSS `@keyframes` only.

11. **`isReportHeld: true` listings are locked** — user cannot edit or delete them. Do not add any workaround that bypasses this.

12. **Sentry only in production** — `if (import.meta.env.MODE === 'production')` guard must stay. Zero overhead in dev.

13. **`pnpm-workspace.yaml` has `minimumReleaseAge: 1440`** — supply-chain attack defense. Do not disable. New packages must have been published for 24+ hours.

14. **`PAGE_SIZE = 30`** in listings.ts — do not change without understanding pagination cursor implications.

15. **Rich text markers in Firestore are intentional** — `**bold**` stored in description field is readable by AI moderation. Do not switch to HTML storage.
