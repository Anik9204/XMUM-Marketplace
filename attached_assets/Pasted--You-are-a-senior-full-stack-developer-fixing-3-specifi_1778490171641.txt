### BUG FIX 1 — "Missing or insufficient permissions" error when sending an inquiry

**Root cause:** In `src/lib/shops.ts`, the `createInquiry` function does this after saving the inquiry:

```ts
await updateDoc(doc(db, "shopListings", data.shopListingId), { inquiryCount: increment(1) });
await updateDoc(doc(db, "shops", data.shopId), { totalInquiries: increment(1) });
```

The Firestore rule for `shopListings` only allows updates by shop members (owner/editors). A buyer is not a shop member, so `updateDoc` on `shopListings` throws "Missing or insufficient permissions". This error surfaces to the user even though the inquiry itself was saved successfully.

**Fix Part A — Update `firestore.rules`:** Add a rule that allows any authenticated user to increment `inquiryCount` on a shop listing, and `totalInquiries` on a shop. The safest way is to allow buyers to update only those specific counter fields. Replace the `shopListings` rule with:

```
match /shopListings/{listingId} {
  allow read: if true;
  allow create: if isSignedIn() && isShopMember(request.resource.data.shopId);
  allow update: if isSignedIn() && (
    isShopMember(resource.data.shopId) ||
    (
      request.resource.data.diff(resource.data).affectedKeys().hasOnly(['inquiryCount']) &&
      isXmuEmail()
    )
  );
  allow delete: if isSignedIn() && isShopMember(resource.data.shopId);
}
```

And replace the `shops` update rule to allow buyers to increment `totalInquiries`:
```
match /shops/{shopId} {
  allow read: if true;
  allow create: if isXmuEmail()
                && request.resource.data.ownerId == request.auth.uid
                && request.resource.data.name is string
                && request.resource.data.name.size() <= 60
                && request.resource.data.editorIds.size() <= 3;
  allow update: if isShopOwner(shopId) || isAdmin() || (
    isXmuEmail() &&
    request.resource.data.diff(resource.data).affectedKeys().hasOnly(['totalInquiries'])
  );
  allow delete: if isShopOwner(shopId) || isAdmin();
}
```

**Fix Part B — Make counter updates non-blocking in `src/lib/shops.ts`:** Even with fixed rules, counter updates should never block or fail the user's inquiry submission. Wrap both counter `updateDoc` calls in a fire-and-forget try/catch so that if they fail, the inquiry is still marked as successfully sent:

Replace these two lines in `createInquiry`:
```ts
await updateDoc(doc(db, "shopListings", data.shopListingId), { inquiryCount: increment(1) });
await updateDoc(doc(db, "shops", data.shopId), { totalInquiries: increment(1) });
```

With:
```ts
// Fire-and-forget counter updates — never block or fail the inquiry submission
Promise.all([
  updateDoc(doc(db, "shopListings", data.shopListingId), { inquiryCount: increment(1) }),
  updateDoc(doc(db, "shops", data.shopId), { totalInquiries: increment(1) }),
]).catch(() => {}); // Silently ignore counter update failures
```

### BUG FIX 2 — Shop banner upload still broken (storage rule still wrong)

**Root cause:** The `storage.rules` file still has:
```
match /shopBanners/{userId}/{allPaths=**} {
  allow write: if request.auth != null
               && request.auth.uid == userId
```

But in `src/lib/shops.ts`, the upload path is:
```ts
ref(storage, `shopBanners/${shopId}/banner.jpg`)
```

The path segment captured as `{userId}` is actually `shopId` (e.g. `WVjojsbJ9Sq1g1Jyvo00`), which will never equal `request.auth.uid`. This is why the upload always silently fails.

**The fix — update `storage.rules`:** Replace the entire `shopBanners` block:

```
match /shopBanners/{shopId}/{allPaths=**} {
  allow read: if true;
  allow write: if request.auth != null
               && request.resource.size < 3 * 1024 * 1024
               && request.resource.contentType.matches('image/.*');
}
```

Note: the `{userId}` variable name is changed to `{shopId}` and the `request.auth.uid == userId` check is removed entirely. Any authenticated user can upload to a shop banner path. This is acceptable because only the shop owner has the `shopId` and can reach the Settings tab.

Also deploy this updated `storage.rules` file — make sure it's committed and pushed so Firebase picks it up. If there's a `firebase.json` file, verify it references `storage.rules` as the storage rules file.
