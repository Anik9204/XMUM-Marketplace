BUG 2 — Shop deletion leaves orphan sub-collection data
File: artifacts/xmum-admin/src/lib/firebase.ts
═══════════════════════════════════════════════════

DIAGNOSIS:
The deleteShop() function in artifacts/xmum-admin/src/lib/firebase.ts
currently only deletes the shops/{shopId} document. It leaves behind ALL
sub-collection and related data:
  - shopListings   (where shopId == shopId)
  - shopInquiries  (where shopId == shopId)
  - shopOrders     (where shopId == shopId)
  - shopReviews    (where shopId == shopId)

These become orphaned documents that waste storage and can cause data
integrity issues.

FIX:
Find the existing deleteShop function in firebase.ts. It currently reads:

  export async function deleteShop(shopId: string) {
    const shopSnap = await getDoc(doc(db, "shops", shopId));
    if (!shopSnap.exists()) throw new Error("Shop not found");
    await deleteDoc(doc(db, "shops", shopId));
  }

Replace it entirely with this version. Do NOT change any other function
in firebase.ts:

  export async function deleteShop(shopId: string) {
    const shopSnap = await getDoc(doc(db, "shops", shopId));
    if (!shopSnap.exists()) throw new Error("Shop not found");

    // Cascade delete all related documents in parallel batches
    const relatedCollections = [
      "shopListings",
      "shopInquiries",
      "shopOrders",
      "shopReviews",
    ];

    await Promise.allSettled(
      relatedCollections.map(async (col) => {
        try {
          const q = query(collection(db, col), where("shopId", "==", shopId));
          const snap = await getDocs(q);
          await Promise.allSettled(snap.docs.map((d) => deleteDoc(d.ref)));
        } catch (err) {
          console.warn(`[deleteShop] failed to clean ${col}:`, err);
        }
      })
    );

    // Delete the shop document last
    await deleteDoc(doc(db, "shops", shopId));
  }

Make sure `getDocs` and `query` and `where` are already imported at the top
of firebase.ts. They should already be there — check before adding. Do not
add duplicate imports.
