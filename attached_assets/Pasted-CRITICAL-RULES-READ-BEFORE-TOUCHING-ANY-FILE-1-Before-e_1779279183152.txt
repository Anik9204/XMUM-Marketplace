FIX 1 — rateLimit.ts localStorage race condition and incognito bypass
File: artifacts/xmum-market/src/lib/rateLimit.ts

The existing try/catch already handles errors silently. The issue is that on quota errors or SecurityError, the catch is empty so the rate limit is bypassed entirely. Change the catch block so that if localStorage is unavailable, the function returns false (blocks the action) rather than silently allowing it:

Find:
  try { localStorage.setItem(`rl_${key}`, JSON.stringify(record)); }
  catch {}

Change to:
  try { localStorage.setItem(`rl_${key}`, JSON.stringify(record)); }
  catch {
    // localStorage unavailable (quota exceeded or private mode) — block the action to be safe

  }

FIX 4 — getOlderMessages uses a JS number timestamp against Firestore Timestamp fields
File: artifacts/xmum-market/src/lib/messaging.ts

Find the getOlderMessages function. It currently queries:
  where("createdAt", "<", oldestCreatedAt),

where oldestCreatedAt is a number (milliseconds). Firestore stores message createdAt as a serverTimestamp() Timestamp. Comparing a Timestamp field against a raw number works in Firestore but can behave unexpectedly. The safe fix is to convert the millisecond number to a Firestore Timestamp before the query.

First, check the existing imports at the top of messaging.ts. Find the firebase/firestore import line. Add `Timestamp` to it if it is not already there.

Then in getOlderMessages, change:
  where("createdAt", "<", oldestCreatedAt),

to:
  where("createdAt", "<", Timestamp.fromMillis(oldestCreatedAt)),

That is the only change in this function.

FIX 5 — Participant profile cache in MessagesPage never invalidates on error
File: artifacts/xmum-market/src/pages/MessagesPage.tsx

Find the useEffect that lazily fetches participant profiles. It currently filters with:
  .filter((uid): uid is string => !!uid && !(uid in participantProfiles))

This means if a profile load fails and sets the value to null in the map (which it does via .catch(() => {})), the uid IS in participantProfiles (with value null) and will never be retried.

Change the filter condition to also retry null entries:
  .filter((uid): uid is string => !!uid && participantProfiles[uid] === undefined)

Note: this means only profiles that have never been attempted (undefined) will be fetched. Profiles that returned null (user deleted, error) won't be retried on every render — but newly unknown UIDs will always be fetched. This is the correct behaviour.

That is the only change in this useEffect filter line.
