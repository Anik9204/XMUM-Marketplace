## BUG 1 — Lost & Found form: contact info not pre-filled + `price: undefined` crashes Firestore

### Problem A — Contact info not pre-filling on Lost & Found

In `PostPage.tsx`, there are two `useEffect` hooks that pre-fill `whatsapp`, `wechat`, and `teams` contact fields from `userProfile` and `user.email`. These hooks have guards like `if (userProfile.whatsapp && !whatsapp)` — the `!whatsapp` condition means once any value is in local state, the hook will never update again. When the user switches to the Lost & Found tab, `userProfile` is already loaded, the effect does not re-run because `userProfile` reference has not changed, and the guard blocks any fill because whatsapp/wechat state is already set.

Fix: Remove the `!whatsapp` and `!wechat` guards from inside the useEffect. Simply always set them from userProfile when userProfile has a value. The effects should unconditionally assign:
```ts
if (userProfile.whatsapp) setWhatsapp(userProfile.whatsapp);
if (userProfile.wechat) setWechat(userProfile.wechat);
```
This is safe because the effect only runs when `userProfile` changes, so it will not overwrite user edits during a single session unless the profile actually reloads.

For the teams field, the existing `useEffect` that sets `setTeams(user.email ?? "")` should also add `type` to its dependency array and re-run whenever the listing type changes, so the field is correctly populated when switching tabs:
```ts
useEffect(() => {
  if (user?.email) setTeams(user.email);
}, [user, type]);
```

### Problem B — `price: undefined` crashes Firestore on Lost & Found submit

In `PostPage.tsx`, inside `handleSubmit`, the listing data object is constructed with:
```ts
price: type === "buy-sell" ? (parseFloat(price) || 0) : undefined,
```

Firestore does not accept `undefined` field values. When `type` is `"lost-found"`, this passes `price: undefined` to `addDoc()` and throws: `"Function addDoc() called with invalid data. Unsupported field value: undefined (found in field price)"`.

Fix: Construct the base listing data object WITHOUT the price field, then conditionally spread price in only for buy-sell listings:

```ts
const baseData = {
  type,
  title,
  description,
  category,
  condition,
  photos: urls,
  userId: user.uid,
  userEmail: user.email ?? "",
  userName: user.email?.split("@")[0] ?? "",
  whatsapp,
  wechat,
  teams,
};

const listingData = type === "buy-sell"
  ? { ...baseData, price: parseFloat(price) || 0 }
  : baseData;

await withTimeout(createListing(listingData), 12_000, "create-listing");
```

The `Listing` type in `src/lib/types.ts` already has `price?: number` (optional), so this is type-safe. No changes needed to `src/lib/types.ts` or `src/lib/listings.ts`.

## BUG 2 — Forgot Password: wrong message for unregistered emails, no resend cooldown, no auto sign-in after reset

### Problem A — "Email sent!" shown for unregistered emails

Firebase's email enumeration protection is enabled by default on all Firebase projects created after September 15, 2023. Under this protection, `sendPasswordResetEmail()` silently succeeds for ANY email address — registered or not — and never throws an error. `fetchSignInMethodsForEmail()` is also deprecated and disabled. This is why unregistered emails show "Email sent! Check your inbox." when no email is actually sent.

Fix: Before calling `sendPasswordResetEmail`, query Firestore to check whether a user document with that email exists. All registered users have a document in the `users` collection with an `email` field (written at sign-up). This is a safe check that does not violate email enumeration protection because it is within our own secured database.

In `src/lib/auth.ts`, add a new exported async function `resetPasswordWithCheck`:

```ts
import { collection, query, where, getDocs, limit } from "firebase/firestore";
import { db } from "./firebase";

export async function resetPasswordWithCheck(email: string): Promise<void> {
  const normalised = email.toLowerCase().trim();
  const q = query(
    collection(db, "users"),
    where("email", "==", normalised),
    limit(1)
  );
  const snap = await getDocs(q);
  if (snap.empty) {
    const err = new Error("No account found with this email address.");
    (err as any).code = "auth/user-not-found";
    throw err;
  }
  await sendPasswordResetEmail(auth, normalised);
}
```
