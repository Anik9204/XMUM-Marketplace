## Issue 1 — Order Questions Must Be Per-Listing, Not Per-Shop

### What is currently happening

The "Order Form Questions" feature currently lives inside the Shop Settings tab in `ShopDashboardPage.tsx`. It calls `saveOrderQuestions(shopId, questions)` which saves the questions array onto the `shops` document in Firestore at `shops/{shopId}.orderQuestions`. This means every listing under the same shop shares the same set of order questions. A food shop cannot have different questions for a nasi lemak listing versus a fried rice listing — every order form asks the same thing regardless of what is being ordered.

### What needs to change

**1A — Add `orderQuestions` field to the `ShopListing` type**

In `lib/types.ts`, add `orderQuestions?: ShopOrderQuestion[]` to the `ShopListing` interface. This field is already defined on the `Shop` interface — it must now also exist on `ShopListing`.

**1B — Add order questions UI to the listing creation form**

In `ShopDashboardPage.tsx`, inside the listing creation form (the `showAddListing` modal/section inside the Listings tab), add an "Order Form Questions" section below the existing listing fields (title, description, price, photos, etc.).

This section must look and work identically to the existing order questions UI currently in the Settings tab:
- A button to add a new question
- Each question has a text input for the question label and a dropdown to select the question type (Text, Number, Yes/No, Multiple Choice)
- Multiple choice questions show an "Add option" button to add answer choices
- Each question has a remove button (trash icon)
- The questions are stored in local component state while the form is open
- When the listing is submitted, the `orderQuestions` array is included in the payload passed to `createShopListing()`

**1C — Add order questions UI to the listing edit form**

Apply the same order questions section to the listing edit form (the edit modal/inline editor in the Listings tab). When the edit form opens for an existing listing, pre-populate the questions from `listing.orderQuestions ?? []`. When the edit is saved, include the updated `orderQuestions` array in the `updateShopListing()` call.

**1D — Update `createShopListing()` in `lib/shops.ts`**

The `createShopListing()` function already spreads the entire data object into `addDoc()`. Since `orderQuestions` is now part of the `ShopListing` type and will be included in the data object, no change to the function signature is needed — but confirm the spread `...data` correctly includes `orderQuestions` and that it is not accidentally stripped.

**1E — Update `OrderFormPage.tsx` to read questions from the listing, not the shop**

In `OrderFormPage.tsx` (or wherever the order form is rendered), the form currently reads `shop.orderQuestions` to display the custom questions. Change this to read `listing.orderQuestions` instead, so each listing's own questions appear on its order form. If `listing.orderQuestions` is empty or undefined, show no custom questions (just the default Quantity field).

**1F — Keep the shop-level order questions in Settings as a fallback (do not remove it)**

The shop-level `orderQuestions` in the Settings tab must remain in place and continue to work. It serves as a default fallback: if a listing has no `orderQuestions` of its own, the order form should fall back to `shop.orderQuestions`. The priority order is: `listing.orderQuestions` (if non-empty) → `shop.orderQuestions` (if non-empty) → no custom questions.

## Issue 4 — Critical: Deleting a Shop Does Not Delete Its Data From Firestore or Firebase Storage

### What is currently happening

When a shop owner deletes their shop from the Settings tab in `ShopDashboardPage.tsx`, the current delete handler only calls `deleteDoc(doc(db, "shops", shopId))` which removes the `shops/{shopId}` document. However, all of the following data is left permanently orphaned in Firestore and Firebase Storage:

- All `shopListings` documents where `shopId == deletedShopId` — remain in Firestore forever
- All `shopInquiries` documents where `shopId == deletedShopId` — remain in Firestore forever
- All `shopOrders` documents where `shopId == deletedShopId` — remain in Firestore forever
- All `shopReviews` documents where `shopId == deletedShopId` — remain in Firestore forever
- The shop banner image at `shopBanners/{uid}/banner_{shopId}.jpg` — remains in Firebase Storage forever
- The shop logo image at `shopLogos/{uid}/logo_{shopId}.jpg` — remains in Firebase Storage forever
- All listing photos at `shopListingPhotos/{shopId}/...` — remain in Firebase Storage forever

### What needs to change

**4A — Create a comprehensive `deleteShopCompletely()` function in `lib/shops.ts`**

Create a new exported async function `deleteShopCompletely(shopId: string, ownerId: string): Promise<void>` that performs the full deletion in this exact sequence:

**Step 1 — Fetch all shop listings**
```
const listingsSnap = await getDocs(query(collection(db, "shopListings"), where("shopId", "==", shopId)));
```

**Step 2 — Delete all listing photos from Firebase Storage**
For each listing document, read its `photos: string[]` array. For each photo URL, extract the storage path and call `deleteObject()`. Wrap each `deleteObject` in try/catch so a missing file does not abort the entire deletion:
```typescript
for (const listing of listingsSnap.docs) {
  const photos: string[] = listing.data().photos ?? [];
  for (const url of photos) {
    try {
      const path = extractStoragePath(url); // same helper used elsewhere in the codebase
      if (path) await deleteObject(ref(storage, path));
    } catch {}
  }
}
```

**Step 3 — Delete all shopListings documents**
```typescript
await Promise.all(listingsSnap.docs.map((d) => deleteDoc(d.ref)));
```

**Step 4 — Delete all shopInquiries documents**
```typescript
const inqSnap = await getDocs(query(collection(db, "shopInquiries"), where("shopId", "==", shopId)));
await Promise.all(inqSnap.docs.map((d) => deleteDoc(d.ref)));
```

**Step 5 — Delete all shopOrders documents**
```typescript
const ordSnap = await getDocs(query(collection(db, "shopOrders"), where("shopId", "==", shopId)));
await Promise.all(ordSnap.docs.map((d) => deleteDoc(d.ref)));
```

**Step 6 — Delete all shopReviews documents**
```typescript

await Promise.all(revSnap.docs.map((d) => deleteDoc(d.ref)));
```

**Step 7 — Delete shop banner and logo from Firebase Storage**
```typescript

try { await deleteObject(ref(storage, `shopLogos/${ownerId}/logo_${shopId}.jpg`)); } catch {}
```

**Step 8 — Delete the shop document itself**
```typescript

```

```typescript
    shopIds: arrayRemove(shopId),
  });

```

**4B — Update the delete shop handler in `ShopDashboardPage.tsx`**

Replace the current delete handler that only calls `deleteDoc()` with a call to the new `deleteShopCompletely(shopId, shop.ownerId)`. The handler must:
- Show a loading spinner and disable the confirm button while deletion is in progress

**4C — Update Firestore security rules**

Confirm that `firestore.rules` allows the shop owner to delete documents in `shopListings`, `shopInquiries`, `shopOrders`, and `shopReviews` where `shopId` matches their shop. If these rules are missing, add them:

**4D — Handle large shops gracefully**

If a shop has more than 500 listings or inquiries, Firestore's `getDocs()` will still return all documents since there is no pagination limit in the delete query. However, `Promise.all()` with hundreds of concurrent deletes can hit Firestore rate limits. Use batched writes instead of `Promise.all` for document deletions:

```typescript
import { writeBatch } from "firebase/firestore";

// Process deletes in batches of 400 (Firestore batch limit is 500)
async function batchDelete(refs: DocumentReference[]): Promise<void> {
  const BATCH_SIZE = 400;
  for (let i = 0; i < refs.length; i += BATCH_SIZE) {
    const batch = writeBatch(db);
    refs.slice(i, i + BATCH_SIZE).forEach((r) => batch.delete(r));
    await batch.commit();
  }
}
```

Use `batchDelete()` for deleting `shopListings`, `shopInquiries`, `shopOrders`, and `shopReviews` documents.
