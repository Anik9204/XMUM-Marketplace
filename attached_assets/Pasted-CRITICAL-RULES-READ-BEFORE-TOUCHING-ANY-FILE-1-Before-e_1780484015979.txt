**TASK: Fix listing limit check bypassed when getCountFromServer fails**

**File to edit:** `artifacts/xmum-market/src/pages/PostPage.tsx` only.

**Read the full file before making any change. Make exactly 2 surgical edits.**

---

**ROOT CAUSE:**

The `fetchRealCount` useEffect (around line 285) fetches the live active listing count via `getCountFromServer`. This call silently fails in production due to `experimentalForceLongPolling`. Its catch block does:

```typescript
if (!cancelled) setRealActiveCount(userProfile?.activeListingCount ?? 0);
```

If `userProfile` has not loaded yet when this catch fires, `userProfile?.activeListingCount` is `undefined`, so `realActiveCount` gets set to `0` and stays `0` forever. This means:

1. The pre-submit check `countToCheck >= 6` evaluates to false (0 >= 6 = false) — the write reaches Firestore
2. Firestore correctly rejects it with `permission-denied`
3. The catch branch also evaluates `activeCount` as `0` — shows the wrong generic message

---

**EDIT 1 — Fix the fetchRealCount catch block**

Find this exact block:
```typescript
      } catch {
        if (!cancelled) setRealActiveCount(userProfile?.activeListingCount ?? 0);
      }
```

Replace it with:
```typescript
      } catch {
        // Do NOT set realActiveCount here — leave it as null so the pre-submit
        // check falls back to userProfile?.activeListingCount at submit time,
        // which is kept live by onSnapshot and will be correct by then.
      }
```

**Why:** leaving `realActiveCount` as `null` means the pre-submit check always falls back to `userProfile?.activeListingCount` which is kept live by `onSnapshot` in AuthContext. By the time the user fills the form and hits submit, `userProfile` will have loaded and `activeListingCount` will be `6`. The pre-submit check will then correctly block the submit before it ever reaches Firestore.

---

**EDIT 2 — Fix the permission-denied catch branch as a safety net**

This handles the edge case where somehow the write still reaches Firestore. Find this exact block:

```typescript
else if (code === "permission-denied") {
  const activeCount = realActiveCount !== null ? realActiveCount : (userProfile?.activeListingCount ?? 0);
  if (activeCount >= 6) {
    setError("You have 6 active listings — the maximum allowed per account on XMUM Market. Delete an existing listing to free up a slot. If you sell regularly, consider opening a Shop in the Shops tab, where you can post up to 30 listings.");
  } else {
    setError("Permission denied. Make sure your email is verified and the Firestore rules are published in Firebase Console.");
  }
}
```

Replace it with:
```typescript
else if (code === "permission-denied") {
  // userProfile is kept live by onSnapshot — activeListingCount is reliable here.
  // Also check activeListingCount (the const derived at render time) as an additional fallback.
  const profileCount = userProfile?.activeListingCount ?? activeListingCount ?? 0;
  const liveCount = realActiveCount ?? 0;
  if (profileCount >= 6 || liveCount >= 6) {
    setError("You have 6 active listings — the maximum allowed per account on XMUM Market. Delete an existing listing to free up a slot. If you sell regularly, consider opening a Shop in the Shops tab, where you can post up to 30 listings.");
  } else {
    setError("Permission denied. Make sure your email is verified and the Firestore rules are published in Firebase Console.");
  }
}
```
