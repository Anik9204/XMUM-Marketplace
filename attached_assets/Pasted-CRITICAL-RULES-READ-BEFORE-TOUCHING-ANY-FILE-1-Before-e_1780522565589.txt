PROBLEM:
When the RichTextEditor is inside the fullscreen modal (fixed inset-0 flex flex-col), the editor area does not scroll internally. Instead, the background page scrolls. This is because the contentEditable div has overflow-y-auto but no bounded height to scroll within — it just expands infinitely.

THE FIX — ONE LINE CHANGE ONLY:

Find the contentEditable div. It currently has this className:
  "flex-1 w-full bg-white dark:bg-slate-900 text-gray-900 dark:text-slate-100 text-sm leading-relaxed focus:outline-none px-3 py-3 min-h-[180px] rounded-b-xl overflow-y-auto rte-editor"

Change ONLY the className by replacing "min-h-[180px]" with "min-h-[180px] max-h-[calc(100vh-160px)]":

New className:
  "flex-1 w-full bg-white dark:bg-slate-900 text-gray-900 dark:text-slate-100 text-sm leading-relaxed focus:outline-none px-3 py-3 min-h-[180px] max-h-[calc(100vh-160px)] rounded-b-xl overflow-y-auto rte-editor"

That is the only change to this file. Do not touch any other line.

REASON: max-h gives the overflow-y-auto a ceiling to scroll within. 160px accounts for the modal header (~56px) and toolbar (~44px) and padding. BUG 2 — "large text" button (TA button) shows ++ raw markers in editor
FILE: artifacts/xmum-market/src/components/RichTextEditor.tsx (same file)
═══════════════════════════════════════════════════════

PROBLEM:
The applyFormat("++") function works by:
1. Reading the DOM to a raw markdown string
2. Injecting ++ markers as raw text into that string
3. Setting el.innerHTML = markdownToHtml(newMd)

The bug: when applyFormat runs, it calls readMarkdown(el) which walks the DOM. At that moment, if the contentEditable already contains formatted <strong> or <em> nodes, the walk can fail to match the selectedText correctly because the selected text in the DOM is the display text but readMarkdown returns a string that includes ** or * markers. So currentMd.indexOf(selectedText) returns -1 and the function returns early without doing anything, or it finds the wrong position.

Additionally, the innerHTML re-render loses scroll position.

THE FIX — Replace the entire applyFormat function and handleBold / handleItalic / handleLarge lines.

Find and remove these lines (the entire applyFormat function plus the three one-liners at the bottom of it):

  const applyFormat = useCallback(
    (marker: string) => {
      ...entire function body...
    },
    [onChange, maxLength]
  );

  const handleBold   = () => applyFormat("**");
  const handleItalic = () => applyFormat("*");
  const handleLarge  = () => applyFormat("++");

Replace the entire block with:

  // ── Toolbar actions ────────────────────────────────────────────────────────
  const handleBold = useCallback(() => {
    const el = editorRef.current;
    if (!el) return;
    const sel = window.getSelection();
    if (!sel || sel.isCollapsed || !sel.toString().trim()) return;
    // execCommand('bold') toggles <strong>/<b> on the selection in-place.
    // htmlToMarkdown already handles both <b> and <strong> → **text**
    document.execCommand("bold", false);
    handleInput();
  }, [handleInput]);

  const handleItalic = useCallback(() => {
    const el = editorRef.current;
    if (!el) return;
    const sel = window.getSelection();
    if (!sel || sel.isCollapsed || !sel.toString().trim()) return;
    // execCommand('italic') toggles <em>/<i> on the selection in-place.
    // htmlToMarkdown already handles both <i> and <em> → *text*
    document.execCommand("italic", false);
    handleInput();
  }, [handleInput]);

  const handleLarge = useCallback(() => {
    const el = editorRef.current;
    if (!el) return;
    const sel = window.getSelection();
    if (!sel || sel.isCollapsed || !sel.toString().trim()) return;

    // Save the selected range before focus calls clear the selection
    const range = sel.getRangeAt(0);
    const selectedText = sel.toString();

    // Check if the selection is already inside a .rte-large span
    let container: Node | null = range.commonAncestorContainer;
    while (container && container !== el) {
      if (
        container.nodeType === Node.ELEMENT_NODE &&
        (container as Element).classList?.contains("rte-large")
      ) {
        // Already large — unwrap: replace the span with its text content
        const span = container as HTMLElement;
        const text = span.textContent ?? "";
        const textNode = document.createTextNode(text);
        span.parentNode?.replaceChild(textNode, span);
        handleInput();
        return;
      }
      container = container.parentNode;
    }

    // Not already large — wrap the selection in a .rte-large span
    try {
      const span = document.createElement("span");
      span.className = "rte-large";
      // surroundContents wraps the selection range in the new element
      range.surroundContents(span);
      handleInput();
    } catch {
      // surroundContents throws if selection crosses element boundaries.
      // In that case, do nothing — safer than a corrupted re-render.
    }
  }, [handleInput]);

IMPORTANT NOTES:
- handleBold and handleItalic call handleInput() after execCommand so the markdown state syncs immediately.
- handleLarge uses range.surroundContents() to wrap the selection in a <span class="rte-large"> directly in the DOM without any innerHTML replacement, so scroll position is never disrupted.
- The "unwrap" path for handleLarge walks up the DOM to find a .rte-large parent and removes it.
- Do NOT remove or change handleInput, handlePaste, markdownToHtml, htmlToMarkdown, readMarkdown, placeCaretAt, or any other function.
- Do NOT change the JSX. The ToolbarButton onClick props already reference handleBold, handleItalic, handleLarge by name.
