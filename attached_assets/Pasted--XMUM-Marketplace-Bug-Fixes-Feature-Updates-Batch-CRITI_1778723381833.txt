## ISSUE 4 — Multi-Photo Listings: Swipeable Photo Gallery with Thumbnail Strip

### Files to edit:
- `src/pages/ListingDetailPage.tsx`
- `src/pages/ShopListingDetailPage.tsx`

### What is happening:
When a listing or shop listing has multiple photos, there is no way for the user to swipe between them or see which photo they are on. Only the first photo is viewable. This needs a swipeable gallery like mudah.my — a main large photo with a thumbnail strip below it.

### Fix for both `ListingDetailPage.tsx` and `ShopListingDetailPage.tsx`:

**Step 1 — Add local state:**
```ts

```

**Step 2 — Replace the current single main photo `<img>` with a gallery block.** Find the existing photo display (it is likely a single `<img>` tag or a simple `<div>` with one image). Replace it with this structure — do not change any surrounding padding, margins, or layout divs outside this block:

```tsx

  <div className="relative w-full">
    {/* Main photo */}
    <div
      className="w-full overflow-hidden relative"
      style={{ aspectRatio: "4/3" }}
    >
      <img
        src={listing.photos[activePhotoIndex]}
        alt={listing.title}
        className="w-full h-full object-cover"
        draggable={false}
      />
      {/* Left / Right arrow buttons — only show if more than 1 photo */}
      {listing.photos.length > 1 && (
        <>
          <button
            onClick={() => setActivePhotoIndex((i) => Math.max(0, i - 1))}
            disabled={activePhotoIndex === 0}
            className="absolute left-2 top-1/2 -translate-y-1/2 bg-black/40 hover:bg-black/60 disabled:opacity-20 text-white rounded-full w-8 h-8 flex items-center justify-center transition z-10"
            aria-label="Previous photo"
          >
            ‹
          </button>
          <button
            onClick={() => setActivePhotoIndex((i) => Math.min(listing.photos.length - 1, i + 1))}
            disabled={activePhotoIndex === listing.photos.length - 1}
            className="absolute right-2 top-1/2 -translate-y-1/2 bg-black/40 hover:bg-black/60 disabled:opacity-20 text-white rounded-full w-8 h-8 flex items-center justify-center transition z-10"
            aria-label="Next photo"
          >
            ›
          </button>
        </>
      )}
    </div>
    {/* Thumbnail strip — only show if more than 1 photo */}
    {listing.photos.length > 1 && (
      <div className="flex gap-2 px-4 pt-2 pb-1 overflow-x-auto scrollbar-hide">
        {listing.photos.map((url, idx) => (
          <button
            key={idx}
            onClick={() => setActivePhotoIndex(idx)}
            className={`shrink-0 w-14 h-14 rounded-lg overflow-hidden border-2 transition ${
              idx === activePhotoIndex
                ? "border-[#003366] dark:border-blue-400"
                : "border-transparent opacity-60"
            }`}
          >
            <img src={url} alt="" className="w-full h-full object-cover" draggable={false} />
          </button>
        ))}
      </div>
    )}
  </div>

```

**Step 3 — Touch/swipe support.** Add swipe gesture support to the main photo div using `onTouchStart` and `onTouchEnd`:
```ts
const touchStartX = useRef<number | null>(null);
```
On the main photo `<div>`:


## ISSUE 5 — Profile Picture Update: Delete Previous Avatar from Storage

### File to edit:
- `src/lib/userProfile.ts`
- `src/pages/SettingsPage.tsx`

### What is happening:
When a user uploads a new profile picture, the new avatar is uploaded to Firebase Storage and the `avatarUrl` in Firestore is updated. However, the old avatar file is never deleted from Firebase Storage, causing orphaned files to accumulate.

### Fix in `src/lib/userProfile.ts`:

Find the `uploadAvatar` function. Before it uploads the new file, it must read the user's current `avatarUrl` from Firestore and delete the old storage object if it exists.

Make this surgical change inside `uploadAvatar`:
```ts
// At the top of uploadAvatar, before the new upload:
const profileSnap = await getDoc(doc(db, "users", uid));
const oldAvatarUrl: string | undefined = profileSnap.data()?.avatarUrl;

// After new file is uploaded and newUrl is obtained, before or after updating Firestore:
if (oldAvatarUrl) {
  try {
    // Extract the storage path from the download URL
    const oldRef = ref(storage, decodeURIComponent(
      oldAvatarUrl.split("/o/")[1]?.split("?")[0] ?? ""
    ));
    await deleteObject(oldRef);
  } catch {
    // Silently ignore — old file may already be deleted or URL may be external
  }
}
```

Make sure `deleteObject` and `ref` are already imported from `firebase/storage` in this file. If not, add them to the existing import line — do not add a new import statement.
