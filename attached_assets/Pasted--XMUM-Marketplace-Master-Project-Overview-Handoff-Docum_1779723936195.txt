## 1. What This Project Is

**XMUM Market** is a student-only online marketplace platform for **Xiamen University Malaysia (XMUM)**. Only students with a verified `@xmu.edu.my` email address can sign up, post listings, or interact with the platform.

The project consists of **two separate frontend apps** sharing one Firebase backend:

| App | Purpose | URL |
|---|---|---|
| **XMUM Market** | Main consumer-facing marketplace for students | `https://www.xmummarket.com` |
| **XMUM Admin** | Internal admin/editor panel for moderating the marketplace | `https://admin.xmummarket.com` |

The platform is **live and actively used by students**. Avoid breaking changes. Vercel handles zero-downtime redeployments.

## 6. Architecture Notes

1. **Shared Firebase project** — both apps read/write the same Firestore and Storage
2. **Routing is wouter** — never suggest react-router-dom
3. **`HomeTab = "all" | ListingType`** — `"all"` is local UI state only, never added to `ListingType` in `types.ts`
4. **Firebase HMR guard** in both `firebase.ts` files: `const app = getApps().length ? getApp() : initializeApp(firebaseConfig)`
5. **`PAGE_SIZE = 30`** in `listings.ts`
6. **All multi-line description fields** use a fullscreen modal editor pattern — NOT inline textarea
7. **Email restriction** — only `@xmu.edu.my` emails can sign up and post. Enforced in both Firestore rules (`isXmuEmail()`) and client-side
8. **`isXmuEmail()`** in Firestore rules requires BOTH matching email domain AND `email_verified == true`
9. **`authDomain`** in `.env` files must always stay as `xmum--market.firebaseapp.com` — never change to custom domain
10. **Offline persistence is disabled** — writes fail fast, no local caching. This is intentional.
11. **Sentry initialized only in production** (`MODE === 'production'`) — zero overhead in dev/preview
12. **`experimentalForceLongPolling: true`** in Firestore config — required for Replit's proxy environment
13. **No framer-motion or GSAP** — all animations use Tailwind or plain CSS `@keyframes`

## 8. Firestore Security Rules — Key Points

File: `artifacts/xmum-market/firestore.rules`

- `isXmuEmail()` = signed in + `@xmu.edu.my` email + email verified
- `isSignedIn()` = any authenticated user
- `isAdmin()` / `isEditorRole()` = checks `role` field in `users/{uid}`
- **Listings:** public read, `isXmuEmail()` to create/update, owner + `isSignedIn()` to delete
- **Reports:** only `isEditorRole()` can read — regular users cannot query reports
- **Users:** `isSignedIn()` to read, owner or admin to update/delete
- **Conversations/messages:** only participants can read/write
- **Report hold:** if `isReportHeld: true` on a listing, user cannot edit, delete the listing, or delete their account until admin resolves it

Deploy rules: Firebase Console → Firestore → Rules → paste and Publish, OR:
```bash
firebase deploy --only firestore:rules --project xmum--market
```

## 9. AI Content Moderation System

This is the most recently built and debugged system. Read carefully.

### How it works

**Flow:** Photos upload → URLs passed to `moderateContent` Cloud Function → Gemini analyzes text + images → result returned → if BLOCKED, photos deleted and post aborted.

**File:** `artifacts/xmum-market/src/lib/aiModerate.ts`
- Calls `moderateContent` via Firebase `httpsCallable`
- Functions region: `asia-southeast1`
- On any error, **fails open** (returns SAFE) — students are never hard-blocked by a function outage
- Supports contexts: `listing`, `shop-listing`, `shop-profile`, `inquiry`, `review`

**File:** `artifacts/functions/src/index.ts` — `moderateContent` function
- **AI model:** `gemini-3.1-flash-lite` via direct REST API call
- **Image moderation:** Google Cloud Vision SafeSearch API (enabled and working)
- **Secret:** `GEMINI_API_KEY` from Firebase Secret Manager
- **CORS:** Explicitly configured to allow `xmummarket.com`, `admin.xmummarket.com`, Vercel preview URLs, localhost
- **IAM:** Cloud Run service set to "Allow public access" (required for Gen 2 callable CORS to work)
- Returns: `{ result: "SAFE" | "FLAGGED" | "BLOCKED", reason: string, suggestion: string }`

### Moderation levels
- **BLOCKED** — post rejected, photos deleted, error shown to student
- **FLAGGED** — post goes through, written to `aiFlaggedContent` collection, visible in Admin → AI Flagged tab
- **SAFE** — post goes through normally

### What is moderated
- Weapons, drugs, sexual content, scams, MLM, hate speech → BLOCKED
- Suspicious job posts, weapon photos with innocent text, price fraud patterns → FLAGGED
- Text-image inconsistency (e.g. title says "book" but photo shows a car) → FLAGGED or BLOCKED based on severity
- Everything else → SAFE

### CSP configuration (important)
Both `artifacts/xmum-market/vercel.json` and `artifacts/xmum-market/index.html` have `https://*.cloudfunctions.net` in their `connect-src` CSP directive. This was required to allow the browser to call the Cloud Function. Do not remove it.

### Deployment note
Deploying `moderateContent` requires:
```bash
firebase deploy --only functions:moderateContent --project xmum--market
```
NOT a GitHub push. Vercel does not deploy functions.

## 15. Content Security Policy

Both apps have CSP headers set in two places each (must be kept in sync):
1. `vercel.json` → `headers` array (enforced in production by Vercel)
2. `index.html` → `<meta http-equiv="Content-Security-Policy">` tag (dev + fallback)

**XMUM Market `connect-src` includes:**
`'self'`, `/api`, `https://*.googleapis.com`, `https://*.firebaseio.com`, `wss://*.firebaseio.com`, `https://identitytoolkit.googleapis.com`, `https://securetoken.googleapis.com`, `https://firebasestorage.googleapis.com`, `https://*.firebaseapp.com`, `https://*.sentry.io`, `https://*.ingest.sentry.io`, `https://*.cloudfunctions.net`

> If you add a new external API call in the frontend, you MUST add its domain to both CSP locations or the browser will silently block it.
