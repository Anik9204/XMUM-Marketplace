### Issue 2 — Fix the Back Button Infinite Loop Between `ShopListingDetailPage` and `ShopPublicPage`

**What is happening:**

The navigation loop occurs because of how the back buttons work on these two pages:

- In `ShopListingDetailPage.tsx` at line 163, the back button does:
  ```javascript
  shop ? navigate(`/shop/${shop.slug}`) : window.history.back()
  ```
  This pushes a **new history entry** for `/shop/{slug}` instead of going back. So the browser history now has: `[..., /market, /shop/slug, /shop-listing/id, /shop/slug]`

- In `ShopPublicPage.tsx` at line 154, the back button does:
  ```javascript
  window.history.back()
  ```
  This goes back one step — which lands on `/shop-listing/id` again (the listing detail page), not on `/market`. So the user is trapped bouncing between the two pages forever.

**Root cause:** `ShopListingDetailPage` uses `navigate()` (which pushes a new entry) instead of `window.history.back()`. This pollutes the browser history stack and causes the loop.

**What needs to change:**

**Fix 1 — `ShopListingDetailPage.tsx` line 163:**

Change the back button `onClick` from:
```javascript
onClick={() => shop ? navigate(`/shop/${shop.slug}`) : window.history.back()}
```
To:
```javascript
onClick={() => window.history.back()}
```

This makes the back button always go back one step in actual browser history, regardless of whether the shop data has loaded. The user came from somewhere — let the browser go back there naturally.

**Fix 2 — `ShopPublicPage.tsx` line 154:**

The `window.history.back()` here is correct in principle, but it breaks if the user lands on `/shop/{slug}` directly (e.g. from a shared link) because there is no history to go back to. Add a safe fallback:

Change:
```javascript
onClick={() => window.history.back()}
```
To:
```javascript
onClick={() => {
  if (window.history.length > 1) {
    window.history.back();
  } else {
    navigate("/market");
  }
}}
```

This means: if there is browser history to go back to, go back (which will correctly land on `/market` or wherever the user came from). If there is no history (direct link), navigate to `/market` as the fallback.
