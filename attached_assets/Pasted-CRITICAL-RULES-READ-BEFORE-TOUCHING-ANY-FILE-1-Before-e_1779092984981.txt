ISSUE: Orphaned Storage files after deletion
═══════════════════════════════════════════

When users or admins delete content, Firebase Storage files 
are being left behind because the deletion functions don't 
clean up all associated photos. This will drain storage over 
time. There are exactly 3 gaps to fix. Do not touch anything 
else.

════════════════════════════
GAP 1 — deleteShopListing() does not delete photos
════════════════════════════

FILE: artifacts/xmum-market/src/lib/shops.ts
FUNCTION: deleteShopListing()

Current behaviour: sets isActive: false on the listing 
document. Never touches Storage at all.

Required fix: Before setting isActive: false, read the 
shopListing document to get its photos array. Then delete 
each photo from Firebase Storage. Only THEN set 
isActive: false on the Firestore document.

The function already has access to storage and deleteObject 
via imports at the top of the file — do NOT add new imports 
unless something is genuinely missing.

The storagePathFromUrl() helper function already exists at 
the bottom of shops.ts — use it. Do NOT write a new one.

Use Promise.allSettled() for photo deletions so a single 
failed photo delete never blocks the whole operation.

If the listing has an active report hold (held === true), 
the existing behaviour is correct — do NOT delete photos 
in that case (evidence must be preserved). Keep that 
logic exactly as-is.

The exact change is:

1. After the report-hold check passes (held === false), 
   fetch the shopListing document:
   const listingSnap = await getDoc(
     doc(db, "shopListings", listingId)
   );

2. Extract photos:
   const photos: string[] = 
     listingSnap.data()?.photos ?? [];

3. Delete photos from storage:
   if (photos.length > 0) {
     await Promise.allSettled(
       photos.map((url) => {
         const path = storagePathFromUrl(url);
         if (!path) return Promise.resolve();
         return deleteObject(
           ref(storage, path)
         ).catch(() => {});
       })
     );
   }

4. Then continue with the existing 
   updateDoc({ isActive: false }) calls as before.

IMPORTANT: getDoc is already imported in shops.ts. 
Verify this before adding it to imports.
