STORAGE RULES (already published in Firebase Console):

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /listings/{userId}/{allPaths=**} {
      allow read: if true;
      allow create, update: if request.auth != null
                   && request.auth.token.email
                      .matches('.*@xmu\\.edu\\.my')
                   && request.resource.size < 5 * 1024 * 1024
                   && request.resource.contentType
                      .matches('image/.*');
      allow delete: if request.auth != null
                   && request.auth.uid == userId
                   && request.auth.token.email
                      .matches('.*@xmu\\.edu\\.my');

    match /avatars/{userId}/{allPaths=**} {
      allow read: if true;
      allow create, update, delete: if request.auth != null
                   && request.auth.uid == userId
                   && request.auth.token.email
                      .matches('.*@xmu\\.edu\\.my')
                   && (request.method == 'delete' || (
                      request.resource.size < 5 * 1024 * 1024
                      && request.resource.contentType
                         .matches('image/.*')));
    }
  }
}

LIKELY CAUSES (in order of probability):

CAUSE 1 — The addDoc call throws but is caught silently:
A try/catch around addDoc swallows the error and the 
function returns success even though nothing was written.
FIX: Rethrow the error from the catch block.

CAUSE 2 — Missing required fields in the data object:
The Firestore rules require auth, but the query also 
filters on status, isArchived, type, and createdAt.
If any are missing from the written document, it writes 
successfully but never appears in the feed.
FIX: Ensure all these fields are in listingData:
  status: 'active'
  isArchived: false
  createdAt: serverTimestamp()
  userId: auth.currentUser.uid
  type: 'buy-sell' or 'lost-found'

CAUSE 3 — The function returns early after image upload:
A return statement after the Storage upload exits before 
the addDoc call is reached.
FIX: Remove the early return.

CAUSE 4 — auth.currentUser is null at write time:
The user object is not available when addDoc runs, 
causing the security rule to reject the write.
FIX: Check auth.currentUser before calling addDoc and 
throw a clear error if it is null. Also call:
  await auth.currentUser.getIdToken(true)
before addDoc to force-refresh the auth token.

CAUSE 5 — db import is broken:
The db export from firebase.ts is undefined at the 
time createListing runs.
FIX: Confirm the import path at the top of listings.ts 
matches the actual location of firebase.ts.
