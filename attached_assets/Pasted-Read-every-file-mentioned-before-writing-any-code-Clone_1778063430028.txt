BUG 1 — PROFILE DATA (avatar, WhatsApp, WeChat) DISAPPEARS ON 
REFRESH OR TAB NAVIGATION
=================================================================

SYMPTOMS:
- User updates avatar, WhatsApp number, or WeChat ID in Settings.
- Save confirms success. Data IS correctly written to Firestore 
  (users/{uid}) and Storage (avatars/{uid}/avatar.*).
- On page refresh OR navigating away and back, the fields in 
  SettingsPage are empty again, and the avatar reverts to default.
- The data still exists in Firebase — the problem is purely a 
  READ/STATE issue on the frontend.

ROOT CAUSE TO INVESTIGATE (read these files first):
1. AuthContext.tsx — Check if it fetches the Firestore user profile 
   doc on auth state change. It likely only stores the Firebase Auth 
   User object (which has displayName/photoURL) but does NOT fetch 
   the extended profile from users/{uid} (whatsapp, wechat, etc.)
2. userProfile.ts — Check the getProfile() function and confirm it 
   reads from users/{uid} in Firestore correctly.
3. SettingsPage.tsx (or ProfilePage.tsx) — Check if the component 
   initializes its local state (name, whatsapp, wechat, avatarUrl) 
   from a profile fetch on mount, or if it only reads from React 
   context which hasn't been populated yet.

REQUIRED FIX:

Fix A — AuthContext.tsx:
After onAuthStateChanged fires with a non-null user, immediately 
fetch the Firestore document at users/{uid} using getProfile(uid). 
Store the result in context as a separate piece of state 
(e.g., `userProfile`). Expose it from the context hook. 
Handle the case where the Firestore doc doesn't exist yet 
(new users before profile setup) gracefully — return null, 
don't crash.

The context shape should be:
  {
    user: FirebaseUser | null,        // Firebase Auth user
    userProfile: UserProfile | null,  // Firestore users/{uid} doc
    loading: boolean,
    refetchProfile: () => Promise<void>  // call this after save
  }

Fix B — SettingsPage.tsx (and any other page reading profile data):
Initialize ALL local form state (displayName, whatsapp, wechat, 
avatarUrl, privacy toggles) from `userProfile` out of AuthContext, 
NOT from `user.displayName` or `user.photoURL` alone. 
Use a useEffect that runs when `userProfile` changes to 
re-populate the form fields:

  useEffect(() => {
    if (userProfile) {
      setName(userProfile.displayName ?? '');
      setWhatsapp(userProfile.whatsapp ?? '');
      setWechat(userProfile.wechat ?? '');
      setAvatarUrl(userProfile.avatarUrl ?? '');
      setShowWhatsApp(userProfile.showWhatsApp ?? true);
      setShowWeChat(userProfile.showWeChat ?? true);
    }
  }, [userProfile]);

Fix C — After a successful save in SettingsPage:
Call `refetchProfile()` from context so the context state is 
refreshed immediately without requiring a full page reload.

Fix D — ProfilePage.tsx (My Listings tab + header avatar):
Ensure the avatar shown in the header/nav and on the Profile page 
reads from `userProfile.avatarUrl` (Firestore), NOT from 
`user.photoURL` (Firebase Auth). These are separate — we store 
the Storage download URL in Firestore, not in the Auth profile.

Fix E — uploadAvatar() in userProfile.ts:
After uploading the image to Storage and getting the download URL, 
confirm it writes BOTH:
  1. To Storage at avatars/{uid}/avatar.{ext}  ✓ (already working)
  2. To Firestore users/{uid} doc as { avatarUrl: downloadURL }
If step 2 is missing or uses setDoc without merge:true, the 
existing profile fields (whatsapp, wechat, etc.) will be wiped 
on avatar upload. Use:
  updateDoc(doc(db, 'users', uid), { avatarUrl: downloadURL })
  NOT setDoc(...) without merge: true.
