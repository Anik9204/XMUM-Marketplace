ROOT CAUSE 2 — getCountFromServer may not be exported by the firebase version in use
════════════════════════════════════

The project uses firebase@^12.12.1. getCountFromServer was introduced in firebase 9.8.0 for the Web Modular SDK, but in some build environments the named export is resolved differently. If the import fails at bundle time, the entire listings.ts module fails to load, causing a white screen.

FIX: Wrap the import defensively and make getTabCounts fail gracefully.

In src/lib/listings.ts:
  1. Keep the existing import as-is BUT wrap the getTabCounts function body in a try/catch that returns all zeros on any error.
  2. Additionally, guard against the case where getCountFromServer might throw a "requires index" Firestore error in production (the 3-field query on type + isArchived + status requires a composite Firestore index that may not exist in production yet).

Replace the entire getTabCounts function with this safer version:

export async function getTabCounts(): Promise<Partial<Record<ListingType, number>>> {
  const types: ListingType[] = ["buy-sell", "lost-found", "jobs", "assistance", "rental"];
  try {
    const counts = await Promise.all(
      types.map(async (type) => {
        try {
          // Only filter by type — avoids needing a composite index
          const q = query(
            collection(db, "listings"),
            where("type", "==", type)
          );
          const snap = await getCountFromServer(q);
          return snap.data().count;
        } catch {
          return 0;
        }
      })
    );
    return Object.fromEntries(types.map((t, i) => [t, counts[i]])) as Record<ListingType, number>;
  } catch {
    // If getCountFromServer is unavailable or fails entirely, return empty
    // so the tab badges just don't render — the app still works
    return {};
  }
}

ROOT CAUSE 4 — No global error boundary means any runtime crash = blank white screen
════════════════════════════════════

The app has no React error boundary. When any of the above errors occur at runtime, React unmounts the entire tree silently and shows a blank page. This makes debugging in production impossible.

FIX: Create src/components/ErrorBoundary.tsx:

import { Component, ReactNode } from "react";

interface Props { children: ReactNode; }
interface State { hasError: boolean; error: Error | null; }

export class ErrorBoundary extends Component<Props, State> {
  constructor(props: Props) {
    super(props);
    this.state = { hasError: false, error: null };
  }
  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }
  componentDidCatch(error: Error, info: React.ErrorInfo) {
    console.error("[ErrorBoundary] Caught error:", error, info);
  }
  render() {
    if (this.state.hasError) {
      return (
        <div className="min-h-screen flex flex-col items-center justify-center px-4 text-center bg-gray-50">
          <div className="max-w-sm">
            <div className="text-5xl mb-4">⚠️</div>
            <h1 className="text-lg font-bold text-gray-800 mb-2">Something went wrong</h1>
            <p className="text-sm text-gray-500 mb-4">
              The app encountered an unexpected error. Please refresh the page.
            </p>
            <p className="text-xs text-red-400 font-mono bg-red-50 p-2 rounded mb-4 text-left break-all">
              {this.state.error?.message ?? "Unknown error"}
            </p>
            <button
              onClick={() => window.location.reload()}
              className="bg-[#003366] text-white px-5 py-2.5 rounded-xl text-sm font-semibold"
            >
              Refresh Page
            </button>
          </div>
        </div>
      );
    }
    return this.props.children;
  }
}

Then in src/main.tsx (or src/App.tsx, whichever wraps the app at root level), wrap the entire app tree with <ErrorBoundary>:

  <ErrorBoundary>
    <App />
  </ErrorBoundary>

ROOT CAUSE 5 — Vercel environment variables may not be set
════════════════════════════════════

The app uses import.meta.env.VITE_FIREBASE_* variables. If these are NOT configured in Vercel's project settings, Firebase initialises with undefined values and the app crashes silently on first Firestore/Auth call.

FIX: In src/lib/firebase.ts, add a startup check that throws a clear, human-readable error before Firebase tries to initialise with undefined config:

Add this block BEFORE the initializeApp call:

const requiredEnvVars = [
  "VITE_FIREBASE_API_KEY",
  "VITE_FIREBASE_AUTH_DOMAIN",
  "VITE_FIREBASE_PROJECT_ID",
  "VITE_FIREBASE_APP_ID",
];
const missingVars = requiredEnvVars.filter(
  (key) => !import.meta.env[key as keyof ImportMeta["env"]]
);
if (missingVars.length > 0) {
  console.error(
    "[firebase] Missing environment variables:",
    missingVars.join(", "),
    "\nMake sure these are set in your Vercel project settings under Settings → Environment Variables."
  );
}

This doesn't block the app from loading but prints a clear error in Vercel's function logs so you can identify the problem immediately.
