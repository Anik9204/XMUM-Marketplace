TASK: Fix silent auth loss causing permission-denied on edit and delete.
Root cause confirmed: experimentalAutoDetectLongPolling: true in firebase.ts causes the Firestore connection to lose its auth token silently when the long-poll connection drops, making request.auth appear null to Firestore rules even though the user is still signed in client-side. The rules are correct. The token is valid. Firestore just isn't seeing it.
File 1: artifacts/xmum-market/src/lib/firebase.ts
Find this block:
tslet db: Firestore;
try {
  db = initializeFirestore(app, {
    experimentalAutoDetectLongPolling: true,
  });
} catch {
  db = getFirestore(app);
}
Replace with:
tslet db: Firestore;
try {
  db = initializeFirestore(app, {
    experimentalAutoDetectLongPolling: true,
    experimentalForceLongPolling: false,
  });
} catch {
  db = getFirestore(app);
}
