TASK: Fix the Firestore auth token issue causing permission-denied on edit and delete.

ROOT CAUSE (confirmed): The Firestore SDK is configured with experimentalForceLongPolling: false, which means it uses WebSocket connections when available. WebSocket connections bake the auth token in at connection time — when Firebase Auth silently refreshes the token (every ~1 hour), the existing WebSocket connection does NOT pick up the new token. Firestore rules then see an expired/invalid request.auth, failing even isSignedIn(). Setting experimentalForceLongPolling: true forces HTTP long-polling instead, where every request is a fresh HTTP call that sends the current auth token — token refreshes are picked up immediately.

FILE TO CHANGE: artifacts/xmum-market/src/lib/firebase.ts

Find this exact block:

  db = initializeFirestore(app, {
    experimentalAutoDetectLongPolling: true,
    experimentalForceLongPolling: false,
  });

Replace with:

  db = initializeFirestore(app, {
    experimentalForceLongPolling: true,
  });

What changed and why:
- Remove experimentalAutoDetectLongPolling: true — this causes the SDK to prefer WebSocket when available, which has the stale-token problem.
- Change experimentalForceLongPolling: false → true — this forces ALL Firestore requests to use HTTP long-polling. Every request is a fresh HTTP call that reads the current token from Firebase Auth's memory. There is no persistent connection that holds a stale token.
- This is a single-line effective change. It does not affect reads, writes, or any other behavior — only the transport layer.

Note: experimentalAutoDetectLongPolling and experimentalForceLongPolling cannot both be true simultaneously — remove experimentalAutoDetectLongPolling entirely when setting experimentalForceLongPolling: true.
