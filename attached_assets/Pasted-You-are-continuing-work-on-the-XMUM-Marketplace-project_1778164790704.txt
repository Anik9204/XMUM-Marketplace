## FIX 1 — Message Seller button does nothing when clicked

### Root cause
The Firestore security rule for conversations currently requires `request.auth.uid in resource.data.participants` on READ and WRITE. However when creating a NEW conversation (the document does not exist yet), `resource` is null — there is no existing document to read `.data.participants` from. This causes the `setDoc` call in `getOrCreateConversation` to silently fail with a permissions error, which is swallowed by the empty `catch {}` block in `handleMessageSeller` in ListingDetailPage. The user sees nothing happen.

### Fix A — Update the Firestore security rules
The user must go to Firebase Console → Firestore → Rules and replace the conversations rules with the following. Show them the exact rules to paste:
match /conversations/{convId} {
  allow read: if request.auth != null
    && request.auth.uid in resource.data.participants;
  allow create: if request.auth != null
    && request.auth.token.email.matches('.*@xmu\\.edu\\.my')
    && request.auth.uid in request.resource.data.participants;
  allow update: if request.auth != null
    && request.auth.uid in resource.data.participants;
  allow delete: if false;
}
match /conversations/{convId}/messages/{msgId} {
  allow read: if request.auth != null
    && request.auth.uid in get(/databases/(database)/documents/conversations/(database)/documents/conversations/
(database)/documents/conversations/(convId)).data.participants;
  allow create: if request.auth != null
    && request.auth.token.email.matches('.*@xmu\\.edu\\.my')
    && request.auth.uid == request.resource.data.senderId;
  allow update, delete: if false;
}

Tell the user: "Replace ONLY the conversations and conversations/{convId}/messages blocks in your Firebase Console Firestore rules. Keep all other rules (users, listings, notifications) exactly as they are."

## FIX 2 — Maybank-style price input (digits fill from right of decimal point)

### How it works
When the user types digits, the price fills from the right of the decimal point, exactly like a point-of-sale terminal or Maybank transfer screen:
- Start: `0.00`
- User types `1`: `0.01`
- User types `2`: `0.12`
- User types `9`: `1.29`
- User types `0`: `12.90`
- User presses Backspace: `1.29`

The underlying value stored in state is an integer representing cents (e.g. 1290 = RM 12.90). The display value is always formatted as `(cents / 100).toFixed(2)`.

### In PostPage.tsx — replace the price input

Replace the `const [price, setPrice] = useState("");` state declaration with:
```ts
const [priceCents, setPriceCents] = useState(0);
```

Replace the entire price input JSX block (the `{type === "buy-sell" && (...)}` block) with:
```tsx
{type === "buy-sell" && (
  <div>
    <label className={labelCls}>{t.price}</label>
    <div className="relative">
      <span className="absolute left-3 top-1/2 -translate-y-1/2 text-gray-400 dark:text-slate-400 text-sm font-medium">RM</span>
      <input
        type="text"
        inputMode="numeric"
        value={(priceCents / 100).toFixed(2)}
        onKeyDown={(e) => {
          if (e.key >= "0" && e.key <= "9") {
            e.preventDefault();
            setPriceCents((prev) => {
              const next = prev * 10 + parseInt(e.key);
              return next > 9999999 ? prev : next; // cap at RM 99999.99
            });
          } else if (e.key === "Backspace") {
            e.preventDefault();
            setPriceCents((prev) => Math.floor(prev / 10));
          }
        }}
        onFocus={(e) => e.target.select()}
        readOnly={false}
        className={`${inputCls} pl-10 text-right font-mono tracking-wide`}
      />
    </div>
    <p className="text-[10px] text-gray-400 dark:text-slate-500 mt-1">
      Type digits to enter price — backspace to correct
    </p>
  </div>
)}
```

Update `handleSubmit` — replace `price: parseFloat(price) || 0` with `price: priceCents / 100` in the `listingData` spread:
```ts
const listingData = type === "buy-sell"
  ? { ...baseData, price: priceCents / 100 }
  : baseData;
```

Also reset `priceCents` to 0 after successful submission (add `setPriceCents(0);` after `setToast(...)` in the success path, or simply let the navigate away handle it since state resets on unmount).
