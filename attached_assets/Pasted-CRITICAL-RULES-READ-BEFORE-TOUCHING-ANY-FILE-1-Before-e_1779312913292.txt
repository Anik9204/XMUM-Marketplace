## Task: Fix "Permission denied" on listing delete and edit for all regular users

### Root cause
Both delete and edit fail with `permission-denied` from Firestore for all regular users. The Firestore `isXmuEmail()` rule requires `email_verified == true` in the Auth token. Even though `getIdToken(true)` is called before the edit save, and even though the stored session shows `emailVerified: true`, Firestore still rejects the write. The token must be force-refreshed AND the user object must be reloaded from Firebase Auth before every Firestore write that requires `isXmuEmail()`. The delete flow in `ProfilePage.tsx` currently does NO token refresh at all before calling `deleteListing()`.

### Fix 1 — ProfilePage.tsx: add token refresh before delete

File: `artifacts/xmum-market/src/pages/ProfilePage.tsx`

Step 1: Add `auth` to the existing import from `"@/lib/firebase"`. The current import line on line 19 is:
```ts
import { logOut } from "@/lib/auth";
```
Change it to:
```ts
import { logOut } from "@/lib/auth";
import { auth } from "@/lib/firebase";
```

Step 2: In the `handleDelete` function, add a token refresh as the very first thing inside the try block. The current try block starts as:
```ts
    try {
      await deleteListing(listing);
```
Change it to:
```ts
    try {
      if (auth.currentUser) {
        await auth.currentUser.reload();
        await auth.currentUser.getIdToken(true);
      }
      await deleteListing(listing);
```

Do NOT touch anything else in handleDelete or anywhere else in ProfilePage.tsx.
