  const params = new URLSearchParams(window.location.search);
  const convId = params.get("conv");
  if (!convId) return;
  const match = conversations.find((c) => c.id === convId);

## BUG 2 — Visiting Settings page for the first time forces dark mode permanently

### What happens
A user who has never changed the theme visits Account Settings. The app
immediately switches to dark mode and stays there even after leaving Settings.
The user has to manually turn it off.

### Root cause
`use-dark-mode.ts` initialises state by reading `localStorage` first, then
falls back to `window.matchMedia("(prefers-color-scheme: dark)").matches`.
On phones (and many laptops) the OS is in dark mode, so `matchMedia` returns
`true`. The `useEffect` then immediately:
1. Adds the `dark` class to `<html>`
2. Writes `"dark"` to `localStorage`

This happens the moment `SettingsPage` mounts — because `useDarkMode()` is
only called in `SettingsPage`, this is the first and only time the hook runs.
From that point the preference is permanently locked in localStorage as dark.

### The fix — only persist to localStorage when the user explicitly toggles

File: `artifacts/xmum-market/src/hooks/use-dark-mode.ts`

Replace the entire file with this new version:

```typescript
import { useState, useEffect, useRef } from "react";

export function useDarkMode() {
  // Track whether the current value came from an explicit user toggle
  // or was just inferred from the OS / localStorage.
  const userHasToggled = useRef(false);

  const [dark, setDark] = useState<boolean>(() => {
    try {
      const stored = localStorage.getItem("xmum-theme");
      // Only use a stored value if the user previously made an explicit choice.
      // A stored value means they toggled before — respect it.
      if (stored === "dark") return true;
      if (stored === "light") return false;
      // No stored preference — read OS preference but DO NOT persist it yet.
      return window.matchMedia("(prefers-color-scheme: dark)").matches;
    } catch {
      return false;
    }
  });

  useEffect(() => {
    const root = document.documentElement;
    if (dark) {
      root.classList.add("dark");
    } else {
      root.classList.remove("dark");
    }
    // Only write to localStorage if the user has explicitly toggled.
    // On first load (userHasToggled.current === false), we apply the class
    // based on OS preference but do NOT commit it to localStorage.
    // This means next time they visit Settings, they get their OS preference
    // again rather than a permanently locked value.
    if (userHasToggled.current) {
      localStorage.setItem("xmum-theme", dark ? "dark" : "light");
    }
  }, [dark]);

  const toggle = () => {
    userHasToggled.current = true;
    setDark((d) => !d);
  };

  return { dark, toggle };
}
```

> **What this changes:**
> - The `dark` class is still applied on load based on OS preference or stored
>   preference — so users who previously chose dark mode still get it immediately.
> - But `localStorage` is only written when `toggle()` is called explicitly.
> - A first-time visitor whose OS is in dark mode will see dark mode on the
>   Settings page toggle correctly reflecting their OS — but it won't be
>   permanently committed until they actually tap the toggle.
> - A user who previously set dark mode via the toggle will still get dark mode
>   on every visit because their localStorage value of `"dark"` is still read
>   and respected.
