ISSUE: New users are not being saved to Firestore users collection
═══════════════════════════════════════════

BACKGROUND:
In artifacts/xmum-market/src/lib/auth.ts, the signUp() function 
creates the Firebase Auth account and then calls setDoc() to write 
the user profile to Firestore. This setDoc() is fire-and-forget 
with a .catch() that silently swallows errors.

The write is failing because of a Firestore security rule conflict:
  allow create: if isOwner(userId) && isXmuEmail();

The isXmuEmail() function inside the Firestore rules requires 
email_verified == true on the auth token. But at signup, the user's 
email is not verified yet — they haven't clicked the link. So 
Firestore rejects the write silently and no users document is 
ever created.

This means new users cannot delete their posts, delete their 
account, or do anything that requires their Firestore profile 
to exist.

═══════════════════════════════════════════
THE FIX — TWO CHANGES
═══════════════════════════════════════════

CHANGE 1 — Fix the Firestore security rule for users create

FILE: artifacts/xmum-market/firestore.rules

Find this rule:
  match /users/{userId} {
    allow create: if isOwner(userId) && isXmuEmail();

Change it to:
  match /users/{userId} {
    allow create: if isOwner(userId) && isSignedIn()
      && request.auth.token.email.matches('.*@xmu\\.edu\\.my$');

EXPLANATION: Remove the email_verified requirement from the 
create rule ONLY. We still require the user to be signed in 
and have an @xmu.edu.my email. We just no longer require 
email_verified at the moment of document creation, because 
the document must be created at signup — before verification 
happens. All other rules (update, delete, and all other 
collections) remain completely unchanged.

Do NOT change any other rule in the file.

CHANGE 2 — Make the Firestore write in signUp() await and 
throw properly so failures are visible

FILE: artifacts/xmum-market/src/lib/auth.ts

Find the signUp() function. Currently the setDoc() call is 
fire-and-forget:

  setDoc(doc(db, "users", cred.user.uid), { ... }).catch((err) => {
    console.warn("[signUp] Firestore user profile write failed (non-fatal):", ...);
  });

Change it so the setDoc() is awaited and throws on failure:

  try {
    await setDoc(doc(db, "users", cred.user.uid), { ... });
  } catch (err: any) {
    console.error("[signUp] Firestore user profile write failed:", err?.code, err?.message);
    throw new Error("profile_create_failed");
  }

Keep ALL the same fields inside the setDoc — do not add or 
remove any fields. Only change how the call is made 
(awaited + throws instead of fire-and-forget).

IMPORTANT: The signUp() function already returns cred.user at 
the end. Make sure it still returns cred.user after the 
try/catch. Do not change the return statement.

CHANGE 3 — Handle the new error in the signup UI

FILE: Find the signup page or component in 
artifacts/xmum-market/src that calls the signUp() function. 
It is likely SignUpPage.tsx or a similar file.

Find where signUp() is called and where errors are caught. 
Add handling for the new "profile_create_failed" error code:

  if (err.message === "profile_create_failed") {
    setError("Account created but profile setup failed. 
              Please contact support.");
  }

This should be added alongside the existing error handling 
cases — do NOT replace them.
