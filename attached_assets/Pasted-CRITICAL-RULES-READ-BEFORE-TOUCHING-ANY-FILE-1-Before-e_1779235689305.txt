Fix: deleteAccount still fails with "Missing or insufficient permissions" after photos are deleted.

The Storage DELETE errors are now 404 (not 403) — photos are deleting fine. The failure is now happening when trying to delete the Firestore listing documents in Step 4.

FILE: artifacts/xmum-market/src/lib/userProfile.ts

In the deleteAccount function, Step 4 currently does:
    await deleteDocWithTimeout(listingDoc.ref);

The problem: if a listing document is missing the `isReportHeld` field entirely (undefined), the Firestore delete rule `resource.data.isReportHeld != true` may behave unexpectedly. More importantly, the `deleteDocWithTimeout` throws on any error and causes the whole Promise.all to reject.

Fix Step 4 to catch and ignore permission errors on individual listing deletes (the photos are already gone, so a listing doc that can't be deleted should not abort the whole account deletion):

Find this exact block inside the listingsSnap.docs.map:
        // Race against 6s timeout as a safety net in case of slow server response
        // in Replit's proxy environment. (Offline persistence is disabled so writes
        // fail fast, but network latency can still cause slow responses.)
        await deleteDocWithTimeout(listingDoc.ref);

Replace with:
        try {
          await deleteDocWithTimeout(listingDoc.ref);
        } catch (err: any) {
          // If delete fails (e.g. missing isReportHeld field on old docs), log and continue
          console.warn("[deleteAccount] Step 4: could not delete listing doc", listingDoc.id, err?.code);
        }

This ensures one problematic listing doc does not abort the entire account deletion flow. The account and user doc will still be deleted even if an old listing doc can't be removed.
