ROOT CAUSE (confirmed by inspecting the actual Firestore document):
Listing documents do NOT have an isReportHeld field on them — it is simply absent.
In Firestore security rules, accessing resource.data.isReportHeld on a document
where the field does not exist throws an error and causes the ENTIRE rule to
default to DENY. This is why every student gets permission-denied on delete and
update. The REST API change and token fixes were all correct but irrelevant —
the rules were throwing before they even evaluated the auth checks.

Find the listings allow update rule (exact current text):

      allow update: if (isSignedIn()
        && resource.data.userId == request.auth.uid
        && resource.data.isReportHeld != true
        && (!request.resource.data.keys().hasAny(["price"])
            || (request.resource.data.price >= 0
                && request.resource.data.price <= 1000000)))
        || (isSignedIn()
            && resource.data.userId == request.auth.uid

Replace with:

      allow update: if (isSignedIn()
        && resource.data.userId == request.auth.uid
        && resource.data.get('isReportHeld', false) != true
        && (!request.resource.data.keys().hasAny(["price"])
            || (request.resource.data.price >= 0
                && request.resource.data.price <= 1000000)))
        || (isSignedIn()
            && resource.data.userId == request.auth.uid
            && resource.data.get('isReportHeld', false) == true
            && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['isArchived', 'status']))

            && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['viewCount']));

Find the listings allow delete rule (exact current text):

      allow delete: if ((isSignedIn() && resource.data.userId == request.auth.uid && resource.data.isReportHeld != true)
        || isEditorRole());

Replace with:

      allow delete: if (isSignedIn() && resource.data.userId == request.auth.uid && resource.data.get('isReportHeld', false) != true)
        || (isSignedIn() && resource.data.userId != request.auth.uid && isEditorRole());

What changed and why:
- resource.data.isReportHeld → resource.data.get('isReportHeld', false) in all 3 places.
  The .get(field, default) syntax safely returns false when the field is missing,
  instead of throwing. This is the entire fix.
- The delete rule also separates the owner branch from the isEditorRole() branch
  so that the get() call inside isEditorRole() is never triggered for regular
  owner-deletes, preventing any secondary failure from that path.
